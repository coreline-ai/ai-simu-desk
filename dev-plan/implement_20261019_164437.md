## 개발 목적

생성 에셋으로 검증한 업무 흐름을 실제 3D 공간과 영속 AI 실행으로 연결한다. 사용자가 맡긴 일의 진행·승인·취소·결과를 서버 기록과 일치하게 확인하도록 한다.

## 개발 범위

- 단일 저장소, Next.js·TypeScript UI, 별도 장기 실행 Node API/Socket.IO/워커, PostgreSQL·Drizzle, Three.js·React Three Fiber를 기본 설계로 한다. 버전은 착수 시 공식 호환성을 확인하고 잠근다.
- 자체 사무실 하나, 직원 둘, 개인 대화와 작업 요청, 실행 상태·승인·취소·결과·기록, 기본 작업 공간 권한을 구현한다.
- 첫 실행 어댑터는 Hermes로 한정한다. 모의 어댑터는 계약 테스트용으로 유지한다.
- 업무 상태 복구를 완료한 뒤 작은 작업 공간의 다중 사용자 상태 공유를 구현한다.
- 단일 호스트 배포부터 검증하고, 실제 필요가 확인되기 전 Redis·분산 큐·추가 마이크로서비스는 도입하지 않는다.

- 앞선 Phase 자체 테스트를 마친 뒤 다음 Phase로 진행한다. 실제 통과만 체크하고 이슈는 해당 Phase에 기록한다.

- `domain/`은 순수 업무 규칙, `application/`은 유스케이스와 포트, `adapters/`는 DB/Hermes/통신 구현, `presentation/`은 HTML/3D 상태 표현을 소유한다.
- 유스케이스가 프레임워크·DB 드라이버·Three 객체를 직접 가져오지 않게 의존성 규칙을 검사한다. 모든 엔터티에 일괄 Repository를 만드는 식의 불필요한 추상화는 피한다.
- 기존 1차 데모의 상태 테스트를 계약 회귀 테스트로 사용하되, 실제 외부 실행의 비동기 취소·조정 규칙을 추가한다.
- 기본 라이브러리·공식 SDK를 우선 사용하고 새 의존성은 필요와 역할을 기록한다.
- DB 스키마 변경, 실제 모델 비용, 공개 서비스 배포는 각 Phase에서 구체적인 변경과 검증 결과를 먼저 준비한다.

## 고정할 데이터 계약

- 자체 `Task`는 사용자가 맡긴 논리적 업무, `Run`은 한 번의 실행 시도다. Hermes 실행 ID는 `Run.externalRef`로 연결한다.
- Hermes 카드·cron을 자체 DB와 동시에 원본으로 운영하지 않는다. 이번 범위는 자체 Task + Hermes 실행으로 제한한다.
- Run 상태는 `queued / running / awaiting_approval / cancel_requested / succeeded / failed / cancelled`다. 연결 건강 상태와 별도로 관리한다.
- 취소 요청 즉시 외부 작업이 멈췄다고 표시하지 않는다. 취소 확인과 완료가 경합하면 DB 버전과 제공자 관측 결과로 확정하고 감사 기록을 남긴다.
- 명령: 작업 공간·행위자·요청 키·스키마 버전·본문. 작업 공간별 요청 키에 DB 유일 제약을 둔다.
- 이벤트: 이벤트 ID·작업 공간·실행 ID·순번·스키마 버전·종류·본문·발생 시각. 중복 수신을 허용하되 화면 반영은 중복 제거한다.
- 토큰·게이트웨이 비밀키는 서버에서만 저장·사용한다. 브라우저와 프롬프트·로그에 넣지 않는다.
- 실제 AI의 도구 실행은 제공자 정책과 사용자 승인 범위를 따른다. 웹 UI가 임의로 승인 제한을 제거하지 않는다.

- [ ] run 시작·델타·도구 진행·승인·최종 결과를 타입이 있는 이벤트로 변환한다.
- [ ] 제공자 세션과 실행 ID, 결과·첨부 참조를 저장한다. 초기에는 텍스트 결과로 범위를 제한한다.

### 자체 테스트
- [ ] 테스트용 Hermes로 실제 시작·스트리밍·승인·거절·취소·실패를 확인한다.
- [ ] 제공자 오류·지원하지 않는 기능·지연 응답·크기 제한을 검증한다.
- [ ] 델타와 최종 응답을 합칠 때 텍스트가 중복되지 않는지 확인한다.

### 이슈 및 수정
