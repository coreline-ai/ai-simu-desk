## 개발 목적
기존 시각 데모를 보존하며 로그인한 사용자의 업무를 DB에 저장하고 서버가 로컬 Fake AI를 실행하는 로컬 제품 흐름을 구현·검증한다. 로그인 → 영속 저장 → Fake AI 실행 순서로 완료 기준을 통과한다.

## 개발 범위
- TypeScript 서버·계약, 검증된 Better Auth의 이메일/비밀번호 로그인·로그아웃·서버 세션 인가.
- Drizzle + 서버 파일에 영속 저장하는 PostgreSQL 기반 PGlite. 사용자/세션/작업 공간/멤버/업무/실행/승인/이벤트, 버전 있는 마이그레이션과 백업·복구 검사.
- Hono Node 서버 하나가 인증·API·정적 제품 화면을 같은 origin으로 제공한다. 기존 2.5D/3D 파일럿은 별도 보존하고 제품에서 3D 렌더러만 재사용한다.
- 사용자의 변경 지시로 실제 외부 모델 연결을 제외하고 서버 설정에 고정된 로컬 Fake AI 어댑터 하나를 구현한다. 요청에 맞춘 규칙 기반 응답·단계·스트리밍을 제공하고 시뮬레이션임을 표시한다.
- 영속 실행 큐, 요청 키 중복 방지, 승인 전 외부 호출 차단, 서버 이벤트 조회와 커서 복구, 제한된 텍스트 생성·시간·출력 크기·동시성, 취소 의미와 재시작 조정.

## 제외 범위
- 공개 배포, OAuth/이메일 발송 설정, 비밀번호 재설정 메일, 운영 SMTP, MFA, 다중 사용자 공동 편집·회의·예약·도구 실행.
- 이번 기능과 무관한 Next.js/React로의 화면 전체 재작성. 기존 GLB/스타일과 순수 상태 경계를 유지한다.
- 실제 PostgreSQL 서버의 운영·복제·다중 호스트. 로컬 단일 프로세스 PGlite를 운영 PostgreSQL 성능 검증으로 표시하지 않는다.

## 공통 진행 규칙
- 앞 단계 자체 테스트를 통과한 뒤 다음 단계로 진행한다. 실제 완료만 체크하고 미검증 조건을 기록한다.
- 비밀값·쿠키·비밀번호·DB 파일은 로그/증거/브라우저 번들에 노출하지 않는다. `.env.local`은 서버 전용이며 Git과 정적 서빙에서 제외한다.
- `server/domain/`: 순수 상태·검증·포트. `server/db/`: 스키마·마이그레이션. `server/application/`: 포트 기반 실행 워커. `server/db/studio-store.ts`: 인가·도메인 전이를 적용하는 트랜잭션 크기 저장 포트 구현. `server/adapters/`: Fake AI/인증. `server/http.ts`: 요청 경계. `product/`: 로그인과 실제 업무 UI.
- 도메인에 HTTP/ORM/렌더러 의존성을 넣지 않고 불필요한 범용 Repository를 만들지 않는다.
- 기존 데이터는 파괴하거나 초기화하지 않는다. 새 DB를 프로젝트 비공개 데이터 폴더에 생성하고 테스트는 별도 임시 DB를 사용한다.

## 결정 기록
- 현재 Docker daemon과 시스템 PostgreSQL이 실행되지 않아 단일 프로세스 로컬 검증은 서버 파일 영속 PGlite로 수행한다. 운영 PostgreSQL 연결/배포는 별도 전환 항목이다.
- 인증은 직접 암호화 구현 대신 Better Auth의 기본 암호 해시·DB 세션·origin 검증을 사용한다. 로컬 이메일 계정이며 이메일 소유 확인을 제공했다고 표시하지 않는다.
- 기존 Next.js/Socket.IO 설계는 후속 규모 검증 시 검토한다. 현재 제품 흐름은 Hono와 영속 이벤트 조회로 구현해 도입 범위를 줄인다.
- 사용자 답변: “Fake AI 를 만들어서 AI처럼 동작 하게 제안 하고 구현”. Hermes·Ollama·실제 외부 모델 호출은 이번 범위에서 제외한다. 로그인·DB·영속 실행은 실제로 구현하며 AI 응답은 명확히 Fake로 구분한다.
