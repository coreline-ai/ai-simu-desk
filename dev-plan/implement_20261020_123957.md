# implement_20261020_123957.md

작성 일시: `2026-10-20 12:39:57 KST`

사용자 요청에 따라 3D 장면 전체의 고품질화·다양화를 최우선으로 정한 개발 제안이다. 최종 검토 R1: `2026-10-20 KST`. 전문가 검토에서 발견한 필수 수정 사항을 반영했다. 첫 실행에서 Phase 0~1 나라 샘플을 검증했다. 이후 사용자의 “1번부터 순차로 작업 진행” 요청에 따라 후속 순서 1~6, Phase 2~6의 전체 로컬 구현·검증으로 범위를 확장했다.

## 개발 목적
기존 2.5D 사무실 이미지의 섬세한 재질·부드러운 빛·풍부한 가구 디테일을 실제 회전·확대·캐릭터 이동이 가능한 3D 공간에 반영한다. 방·가구·다섯 캐릭터의 시각적 완성도를 함께 높이고, 일어서기·걷기·휴식에도 외형과 접지가 자연스럽게 유지되게 한다.

목표 스타일은 따뜻한 미니어처 스튜디오다. 얼굴과 비율은 친근한 스타일을 유지하면서 목재·천·금속·유리·식물의 재질 차이와 생활 소품을 정교하게 표현한다.

## 개발 범위
- P0: 한 구역의 실제 3D 품질 샘플 → 공통 재질·조명 → 전체 사무실 교체.
- P0: 5명의 얼굴/헤어/의상/손·발 외형 차이, 움직임을 위한 전신 관절 구조.
- P1: 역할별 작업 공간·소품, 휴게 공간, 낮/저녁 조명 변형과 고정된 시작 구도.
- P1: 기지개·일어서기·걷기·휴식·복귀. 기존 생활 동작 계획의 이동/예약/업무 우선 정책을 재사용한다.
- 로컬 4180 제품에 새 v5 에셋과 렌더 설정을 연결하고 기존 5명 협업·인계·정지·모바일 UI를 회귀 검증한다.

## 제외 범위
결과 보드·검토 도구·새 AI 기능·DB 변경, 외부 서비스/DB·유료 에셋 구매·공개 배포, 새 캐릭터 추가·음성·복잡한 물리 시뮬레이션·임의 자유 이동은 포함하지 않는다. 현재 요청에 따라 로컬 Phase 0~6을 구현·검증한다. 커밋·푸시는 이번 요청에 포함하지 않는다.

- 품질 기준은 실제 GLB를 로컬 웹에서 렌더한 화면으로 판정한다. 전체 보기·가까이 보기·움직이는 구간을 모두 기록한다.

- 기존 Three.js와 GLB 파이프라인을 우선 활용한다. 새 도구 도입 전 로컬 원본/UV/리그의 생성·편집·재빌드 절차부터 입증한다. 단순 도형의 개수만 늘리는 것으로 고품질 달성을 판단하지 않는다.
- 모든 텍스처/모델은 로컬에서 재현 가능한 소스·생성 절차·출처를 기록한다. 손/팔·머리·옷·가구의 경계가 움직여도 깨지지 않게 한다.
- 서버 업무 상태·저장 답변·공간 권한은 유지한다. 시각적 휴식은 서버 실행을 멈추거나 지연하지 않는다.

## 필수 에셋·동작 인수 목록
- 캐릭터 5개: 공유 신체 구조를 쓰되 헤어 실루엣·얼굴 요소·의상 형태를 서로 구별한다. 색상만 바꾼 복제는 개별 디자인 완료로 세지 않는다.
- 작업 공간 키트 5개: 키트마다 소품 3개 이상을 배치하고 그중 2개 이상은 역할을 식별할 수 있는 형태/기능을 갖게 한다. 공통 펜·책 등은 재사용한다.
- 환경: 소파/러그/휴게 테이블/책장/창·벽·바닥 세트, 의자 디자인 2종 이상, 실루엣이 다른 식물 3종 이상. 같은 식물의 크기 변경만으로 종을 늘리지 않는다.
- 재질군 7개: 목재·천·금속·플라스틱·유리·돌·잎. 얼굴/머리는 별도 조절하며 물체의 실제 거칠기/색/반사 차이가 읽혀야 한다.
- 캐릭터별 필수 동작 **21종**, 5명 총 **105개 이름 바인딩**: 기존 `idle/typing/thinking/waiting/success/error/blink/preparing/reviewing/sending/receiving/acknowledge` + 신규 `stretch/shoulder_roll/wrist_relax/stand_up/standing/walk/turn/sit_down/rest`.
- 같은 이름의 클립을 공유 구조로 생성할 수 있지만, 최소 `idle/typing/stretch/rest`는 동료별 포즈·타이밍 프로필을 갖게 한다. 단순 재생 속도 차이만으로 다양화를 완료 처리하지 않는다.
- 명세에 assetId·배치·원본/생성 소스·출처·재질/텍스처·공유 항목·크기·해시·사용 클립·검수 결과를 기록한다. 위 수량은 전체 버전 완료 기준이며 초기 샘플에 전부 넣지는 않는다.

## 에셋·런타임 계약
- `manifest-v5`/GLB metadata에 schemaVersion, metres/+Y/floorY, actor ID와 고유 노드 바인딩, head/seat/foot anchor, 자리·휴식 지점·장애물·통로, 서 있는/동작별 bounds, 클립 이름·길이·반복/1회 속성을 고정한다.
- 데이터 흐름: 서버 스냅샷 → 기존 업무 표시 상태 → 생활 동작 정책 → 캐릭터별 이동/포즈 → 렌더 → 실제 머리 위치의 이름표/카메라. 시연 버튼은 생활 동작 정책에만 입력한다.
- runtime의 `ActorRoot`만 세계 위치·yaw를 변경하고, in-place 클립은 하위 `RigRoot`의 자세만 변경한다. clip과 길찾기가 같은 루트 위치를 동시에 변경하지 않는다. 눈 깜빡임·시선 보정은 정해진 노드에만 적용하고 보정값을 매 프레임 누적하지 않는다.
- v4의 `<actorId>_<pose>` 이름 의미는 유지한다. v5 필수 클립/anchor 누락은 로더 검증 실패로 처리한다. 지원되지 않는 걷기를 조용히 idle로 대체하지 않는다.
- 전신은 노드 관절 구조부터 검증한다. 팔을 올렸을 때 어깨/옷 경계가 끊어지면 해당 몸통/의상에 한정한 스키닝을 Phase 0에서 검증하고 결정한다. 결정한 방식을 5명에게 공유하며 전원 제작 후 리깅 방식을 바꾸지 않는다.
- GLB로 내보낸 뒤 실제 GLTFLoader로 재수입해 UV·색/요철/거칠기 맵·alpha·공유 재질·스킨/관절·클립·metadata가 유지되는지 검사한다. 기본 PNG/JPEG·현재 로더 지원 범위부터 사용하고 압축/새 decoder는 실제 필요가 확인될 때만 추가한다.
- 색 텍스처는 sRGB, normal/roughness 등 데이터 맵은 색 변환을 하지 않는 입력으로 구분하고, 출력/톤 매핑은 한 번만 적용한다. 구운 음영은 조명 변경과 충돌하지 않는 정적 환경 AO를 우선하며, 움직이는 캐릭터와 의자에는 고정된 캐릭터 그림자를 굽지 않는다.
- 높음/균형/낮음은 같은 actor ID·관절/클립/anchor와 이동 상태를 유지한다. 해상도/텍스처·정적 소품의 세부 수준을 낮춰도 이름표·외형 차이·필수 동작은 유지한다.

## 활동 전환·안전 조건
- 전환은 `착석 대기/업무 → 스트레칭 또는 기립 → 서기/회전 → 걷기 → 휴식 → 복귀 → 자리 정렬 → 착석`으로 관리한다. 동작 종료 이벤트만으로 무조건 idle에 보내지 않는다.
- 상체 스트레칭은 새 업무에 맞춰 자연스럽게 끝낸다. 기립/보행 도중에는 현재 접지 단계에서 안전하게 복귀한다. 도착 전에는 ‘업무 진행 · 복귀 중’을 표시하고 타이핑/인계 손짓을 재생하지 않는다. 인계 카드는 즉시 갱신하며 지나간 손짓은 나중에 몰아 재생하지 않는다.
- 우선순위는 정지/동작 줄이기 → 최신 업무에 따른 안전 복귀 → 유효한 현재 인계 → 수동 대기 시연 → 자동 생활 동작이다. 서버 실패/취소는 시각 상태와 분리하고, 통로 계산 실패는 안전 대기+예약 해제로 처리한다.
- 이동 시간은 렌더의 한 단조 시계로 계산하며 정지/숨김 동안 진행하지 않는다. 새 스냅샷은 모션 시간을 초기화하지 않는다. model/공간 epoch·actor·cycle ID로 늦은 load/종료 콜백을 무효화한다.
- 충돌 영역은 가구 bounds와 동작별 캐릭터 폭으로 계산한다. 통로 여유는 보행 몸통 반경의 두 배+0.1m 이상을 초기 기준으로 하고 Phase 0에서 실제 팔/의자 궤적과 함께 확정한다.
- 보행 디딤 구간의 발 미끄러짐 2cm 이하, 바닥 침투 1cm 이하를 초기 검증 오차로 둔다. 발 들기 구간에는 ‘고정 접지’ 조건을 적용하지 않는다. 30/60Hz·가변 프레임에서도 같은 거리와 종료 위치를 확인한다.
- 동시에 이동은 1명, 대기 순서는 순환 배정하고 반복 예약을 막는다. 멈춤/공간 전환 시 예약을 해제하고 복귀 후 재검사한다. 10분 연속 업무 대기 시험에서 5명 모두 스트레칭과 최소 1회 휴식 왕복을 수행해야 한다.

## 시각 품질 게이트
- 기준 카메라/줌·해상도/DPR·중립 광원·샘플 영역을 고정한다. 2.5D 이미지는 스타일 기준이며 똑같은 픽셀/광학 결과를 요구하는 기준은 아니다.
- 형상/실루엣, 재질/UV, 빛/접촉, 캐릭터/관절 연결, 배치/식별의 5개 항목을 전후 캡처와 함께 1~5점 검수한다. 각 항목 4점 이상과 관통/분리/누락 같은 중대 결함 0개를 확장 조건으로 한다. 점수는 근거를 남기는 시각 판정이며 객관적 화질 계측으로 표현하지 않는다.
- 전체 보기에서 실루엣·색 구분, 가까이 보기에서 질감·마감, 팔 올리기/기립/회전에서 연결부·그림자를 별도로 확인한다. 같은 밝기 증가나 색상 변경만으로 통과시키지 않는다.

## 전환·실패·v4 복구
- v5 manifest와 에셋을 먼저 읽고 필수 계약을 확인한 뒤 화면에 교체한다. 실패/중단된 모델은 해제하고 v4 경로를 유지한다. actor·epoch·취소 신호로 늦게 완료된 load가 현재 장면을 덮지 않게 한다.
- v5가 필수 계약을 만족하지 않으면 v4 기본 장면과 지원 가능한 동작으로 복구하고 생활 이동 버튼을 비활성화한다. 이것을 v5 검증 통과로 기록하지 않는다.
- 제품 빌드에 복구용 v4 파일과 일치하는 코드/명세를 함께 포함한다. GLB 파일 하나만 이전 버전으로 덮어쓰는 방식으로 복구하지 않는다.
- 재질/형상/텍스처·선택한 후처리 자원의 소유권을 로더 세대 단위로 관리한다. 같은 로드 안에서 공유된 자원을 중복 dispose하지 않고, 새 장면에서 쓰는 자원을 이전 장면 정리 중 해제하지 않는다.
- 실패 texture/GLB, 품질 전환 20회, 모델 교체 10회, loading 중 공간 전환/화면 닫기, WebGL loss/restore를 실제 경로에서 검사한다. 워밍업 후 안정 구간 대비 자원 수가 반복마다 증가하면 완료하지 않는다.

## 첫 확인 가능한 결과
**나라 1명 + 책상/의자 + 창가/바닥**을 실제 3D로 먼저 완성한다. 기존 화면과 같은 조건에서 재질·얼굴·가구·그림자 차이를 확인한 뒤, 검증한 품질을 다섯 자리와 사무실 전체에 적용한다. 전체 보강은 이 계획의 필수 완료 범위다.
