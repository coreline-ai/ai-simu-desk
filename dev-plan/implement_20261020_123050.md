## Phase 2. 역할별 수정·인계·비교
### 목표
완료된 한 역할의 결과를 원본으로 후속 작업을 만들고 변경 영향을 확인한다.

### 구현 태스크
- [ ] 기존 sourceRunId/mode 계약에 선택적 원본 역할 식별자를 추가한다. 서버가 같은 공간의 완료 원본 metadata에서 역할과 본문을 검증·추출한다. 클라이언트가 보낸 원본 본문·offset은 신뢰하지 않는다.
- [ ] 원본 run ID·역할·결과 버전·선택 본문·공통 조건을 sourceContext에 고정한다. 기존 전체 결과 후속 작업과 오래된 sourceContext는 계속 읽을 수 있게 한다.
- [ ] 선택 역할에 ‘3줄로 요약’·‘표로 정리’를 제공하고, 인계는 다른 동료 4명 중 선택하게 한다. 기본 제안은 다음 역할이며 레오는 나라로 제안한다. 인계 초안은 역할별 고정 문구를 사용하고 실행 전 승인 규칙을 유지한다.
- [ ] 새 실행은 기존 단일 담당 경로를 사용한다. 한 공간의 활성 실행 1개, 중복 요청 키, 승인·취소·재시도를 유지한다. 자유로운 재작성 지시는 기존 지원 범위를 안내한다.
- [ ] 비교의 원본을 선택 역할 본문으로 맞춘다. 서버 조회는 공간·원본 ID·역할로 제한하고 페이지를 나눠 최근 20개 밖의 후속 실행도 확인하게 한다. 기존 검색·줄 비교를 재사용한다.
- [ ] 후속 결과가 성공하면 원본 보드에 별도 수정 분기로 연결한다. 그 뒤 역할에는 ‘원본 기준 작성 · 수정 반영 검토 필요’를 표시한다. 원본 성공 상태·본문이나 후속 역할 결과를 자동으로 바꾸지 않는다.

## Phase 3. 공동 검토 체크리스트
### 목표
사람이 확인한 내용과 자동 생성 완료를 구분해 공유한다.

### 구현 태스크
- [ ] 완료된 역할 결과에 ‘요청 조건 확인’·‘산출물 확인’·‘다음 인계 내용 확인’의 고정 3항목을 제공한다. 생성된 답변을 실행했다고 해서 자동 체크하지 않는다.
- [ ] 로컬 DB에 workspace/run/역할/고정 항목 ID, revision, 확인 여부·확인자·시각을 저장하는 최소 테이블을 추가한다. 기존 결과는 기본 미확인으로 취급한다.
- [ ] 소유자·업무 참여자만 변경하고 보기 전용은 조회한다. 서버가 완료 원본/유효 역할/현재 공간 권한과 revision을 확인하며 충돌은 409로 반환한다.
- [ ] 검토 변경을 기존 공간 이벤트/동기화에 연결한다. UI는 충돌 시 서버 값을 다시 읽고 다른 사용자의 변경을 자동 덮어쓰지 않는다.
- [ ] Phase 2에서 만든 새 실행의 검토 상태는 별도 미확인으로 시작한다. 원본 체크를 새 결과로 승계하지 않는다. 체크리스트에 따라 ‘미확인/일부 확인/검토 확인’을 표시하되 실제 구현·테스트 완료를 주장하지 않는다.

### 자체 테스트
