## 개발 목적
5명의 보행 외 동작을 자체 검토하고, 성격과 역할이 드러나는 자연스러운 업무·대화·휴식 동작의 구현 순서를 고정한다. 2026-10-23 요청으로 완료된 P0에 이어 3~7번/P1~P2 전체를 순차 구현한다. 개인별 업무·음용·대화·인계와 필요한 접촉 에셋, 종합 검수·기본 제품 로컬 적용을 포함한다.

## 개발 범위
- 공간 v9·보행 보강 v11을 기준으로 나라·소라·준·민·레오의 개인별 동작 의도를 기존 리그/소품에 연결한다.
- P0 적용 순서/프로파일 정리·기립/착석/경청, P1 역할 업무·컵/커피·소파/응답, P2 보드/업무 반응·필요 에셋/비교 검증.
- 기존 v11 비교를 보존하고 실험 동작은 별도 차기 화면에서 선행 검증한다.

## 공통 진행 규칙
- 각 Phase는 자체 테스트 완료 후에만 다음 단계로 진행한다. 이슈는 해당 단계 안에서 해결하고 실제 완료만 체크한다.
- 실제 사용자 DB를 검수 데이터로 쓰지 않는다. 시각 배속 x1/x1.5/x2/x3은 업무·인증·DB 시간을 변경하지 않는다.
- 루트 이동/발 접지는 경로 제어, 엉덩이/손 지지는 해당 지지 솔버, 소품 소유 손은 해당 소품 솔버가 최종 결정한다. 개인 연출은 그 전에 의도를 제공한다.
- `HUMAN_PROFILES`와 기존 역할/휴식 데이터를 필요한 만큼 확장한다. 별도의 중복 인물 테이블이나 전면 애니메이션 프레임워크를 만들지 않는다.
- 컵/문서/마커의 단일 소유권·관절/지골 길이를 보존한다. 팔/소품 스케일을 늘려 접촉 오차를 숨기지 않는다.
- 연출은 준비→행동→정리와 정지 구간을 가진다. 손/시선 대상·완료 이벤트는 결정적이며 추가 비동기 타이머나 관절 전체의 무작위 흔들림을 넣지 않는다.
- 실제 업무·취소·참가자 종료·정지·숨김·모션 축소·화면 폐기 때 기존 회수/재개 규칙에 양보한다.
- 기존 API/의존성과 리그를 우선 사용하고 범위 밖 확장을 하지 않는다. 새 동적 노드가 필요하면 공유 스키마/버전과 해제를 함께 검토한다.
