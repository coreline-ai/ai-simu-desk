## 개발 목적
캐릭터가 실제 공간을 이용하도록 책상→소파 휴식→컵 사용→회의→업무 복귀를 연결한다. 동작 종류와 함께 손·발·좌석의 접촉, 이동의 연속성, 업무 도착 시 중단을 개선한다.

## 개발 범위
- 나라 한 명의 목적지 이동·소파 착석을 먼저 검증하고 다섯 명으로 확장한다.
- 컵 집기·들기·한 모금·내려놓기와 나라·준 2인 회의를 순차 구현한다.
- 현 9.6×7.6m 안에서 경로·좌석·컵의 점유를 관리하고 실제 업무 상태를 우선한다.
- 기존 v6를 보존하는 별도 활동 검수 페이지/후보 에셋을 만든다. 최종 회귀 통과 후 제품에 연결한다.

## 제외 범위

## 공통 진행 규칙
- 앞선 Phase 자체 테스트를 완료한 뒤 다음 Phase로 진행하며 이슈는 발견한 Phase에 기록한다.
- actor ID·업무 cue·루트 이동의 소유권을 유지한다. 서버 업무는 이동/소품 정리를 기다리지 않는다.
- 로컬 시각 시계 하나로 이동·접촉·소품 전환을 구동한다. 정지 중 예약 만료/컵 전환이 진행되지 않게 한다.
- 우선순위는 실제 업무/승인·인계 cue→안전한 복귀→명시적 시연→자율 생활 동작이다. 회의 참가자의 업무 도착도 개인별로 처리한다.
- 임계 지점의 컵 소유권 전환은 한 번만 실행하고, 정지/숨김/재로드/공간 이동에서 중복 재생하지 않는다.
- 이동은 저작한 경유점과 공유 구간 예약으로 시작한다. 길이 막히면 책상 대기·다른 활동으로 대체하며 억지로 통과시키지 않는다.
- 기존 Three.js·기하/관절/GLB 파이프라인을 사용한다. 새 라이브러리나 제작 도구는 필요성이 확인된 경우에만 검토한다.
- 시각 회의/컵 동작은 클라이언트 연출이다. 서버 결과를 읽지 않고 새 업무를 만들지 않으며 다른 사용자와 시각 프레임이 같다고 보장하지 않는다.
- 체크박스·검수 결과는 실행한 사실만 반영한다. 물리 기기와 OS 환경 미검증은 별도 유지한다.

- 신규 `pilot-3d/activities/anchors.mjs`: 좌석·접근·발·손잡이·테이블 놓는 위치와 사용 정원. 모델에서 읽은 실제 좌표를 사용한다.

- 기존 `ambient-motion.mjs`: 업무 우선 스케줄·활동 선택·예약 호출. 서버 업무 상태 계산은 하지 않는다.
- 기존 모델/최적화/로더/계약/빌드: 상호작용 컵·잡는 손이 인스턴싱/병합으로 사라지지 않게 보존. 후보 modelVersion과 interactionSchemaVersion을 명시하고 v6 원본 계약을 보존한다.
- 신규 `/demos/activities/` 페이지·검사·QA 기록: v6 전환 비교, 자세/접촉점 보기, 구간 정지/업무 중단 재현. 검수 도구를 제품 주요 조작에 노출하지 않는다.

- [ ] 나라의 컵 한 모금과 중단·정리 과정이 검수 페이지에서 재현된다.

## Phase 4. 나라·준 2인 회의 — P1
### 구현 태스크
- [ ] 작은 회의 테이블 주변의 두 접근/대기 위치와 컵 놓는 점을 확보한다. 회의 위치를 함께 예약한 뒤 공유 통로를 차례로 사용한다.
- [ ] 서서 대화→발언자 손짓→경청자 끄덕임/시선→교대→컵 정리→각자 복귀를 구현한다. 컵 든 손은 안정화하고 빈손만 크게 제스처한다.
- [ ] 한 명에게 업무가 오면 그 사람은 컵을 정리하고 복귀한다. 다른 사람은 새 참가자를 무한 대기하지 않고 정리 후 복귀한다.
### 자체 테스트
- [ ] 도착 시간 차이·상대 취소·동시 업무·반복 cue·시선 대상 소멸에서 중복 참가/영구 대기/팔 관통이 없는지 확인한다.
- [ ] 회의 연출이 실제 서버 요청·승인·결과·인계 순서를 변경하지 않고, 비참가자의 작업 동작도 유지되는지 확인한다.
### 완료 조건
- [ ] 나라·준의 컵 든 회의와 개인별 업무 복귀를 실제 웹에서 확인한다.

## Phase 5. 5명 확장과 변주 — P1
### 구현 태스크
- [ ] 다섯 명의 체형/옷/머리에 소파·손·컵 자세를 각각 보정한다. 소파 정원은 최대 2인으로 제한하고 좌석별 장식을 정리한다.
- [ ] 회의 착석용 의자와 접근 여유를 먼저 검수한다. 현 구역이 허용하는 2~3인부터 적용하고, 전원 동시 회의는 5개 위치·의자/복귀 경로가 들어가는 별도 배치 검증을 통과할 때만 확장한다.
- [ ] 소파: 기대기/가볍게 둘러보기/손 모으기, 컵: 들기/한 모금/내려놓기, 회의: 설명/경청/메모처럼 2~3개 의미 있는 변주를 추가한다.
- [ ] 인물별 휴식 간격·체류 시간·동작 선택을 재현 가능한 seed와 cooldown으로 분산한다. 시연의 즉시 재생과 자연스러운 자동 빈도를 구분한다.
### 자체 테스트
- [ ] 5명×소파/컵/회의 접촉 자세, 좁은 화면 선택/이름표, 다섯 명 동시 요청 시 정원·대기 공정성·순환 대기를 검사한다.
- [ ] 공동 통로의 보행 겹침·컵 든 팔과 가구/다른 사람 간 충돌, 장기 대기 시 안전 대체가 동작하는지 확인한다.
### 완료 조건
- [ ] 5명이 서로 다른 생활/업무 동작을 수행하며 정원을 초과하지 않고 모두 책상으로 돌아온다. 5인 동시 착석 회의 가능 여부를 별도 기록한다.

## Phase 6. 통합 검수·제품 적용 — P0 게이트
### 구현 태스크
- [ ] v6 기본 화면과 후보의 전체/소파/컵 근접/회의 구도를 같은 카메라·DPR·화질로 비교하고 통과 후 제품에 적용한다.
- [ ] 동작 파일/anchor 누락 시 v6로 안전 복구한다. 후보 버전과 v6 원본 계약을 분리하고 로더·렌더러·환경을 함께 복구한다.
### 자체 테스트
- [ ] 기존 147개와 신규 이동·점유·소유권·중단·회의 검사를 통과한다. 타입/구문/경계/제품 빌드와 실제 5역할·4회 업무 인계를 다시 확인한다.
- [ ] 생활 동작 10분 및 업무/소파/컵/회의 혼합 30분을 실제 실행한다. 10회 재로드·20회 화질/시간대 전환에서 단일 canvas와 자원 수 안정·예약/컵 정리를 확인한다.
- [ ] v6와 동일 조건 30초×3회: 데스크톱 p50≤20ms/p95≤33.3ms, 호출·삼각형 각각 v6 대비 +10% 이내를 관리선으로 삼는다. 초과 시 가려진 형상/공유 재질/동적 소품 수부터 보정하고 근거를 기록한다.
- [ ] 필수 초기 자산 15MiB 이내를 유지한다. 컵·손·의자/클립 증가와 별도 로드 비용을 집계하고 GPU/heap 실측과 자원 개수 추정을 구분한다.
- [ ] 320~1440px·키보드 선택·모션 정지·숨김 복귀·공간 이동을 검사한다. 실기기 DPR 2/터치/발열·실제 OS 설정은 가능한 기기에서 수행하고 불가능하면 미검증으로 남긴다.
### 완료 조건
- [ ] 동작·업무 회귀·성능·복구를 통과하고 미검증 항목을 명시한 QA 기록과 비교 웹을 제공한다.

## QA 관점
- [ ] 좌면/발/손/컵 접촉은 근접 시점과 연속 전환으로 확인한다. 최종 정지 자세만으로 통과시키지 않는다.
- [ ] 컵을 든 채 업무 도착, 소파 두 자리 동시 요청, 회의 참가 중 로그아웃/공간 이동, 숨김 중 업무 완료를 재현한다.
- [ ] 임계 프레임을 건너뛰는 큰 dt·낮은 프레임률에서도 소품 전환은 정확히 한 번 실행한다.
- [ ] 활동별 자원을 일부 점유한 채 서로 기다리는 순환 대기를 막고, 예약 해제·대체 활동으로 회복되는지 확인한다.
- [ ] 컵/손 노드가 최적화로 병합되거나 GLB 재수입 후 부착점이 사라지지 않는지 검사한다.
- [ ] 생활 동작 시각 차이를 공동 공간의 실제 업무 상태 불일치로 표시하지 않는다.
- [ ] 고정 사람 그림자·추가 그림자 광원·과한 후처리로 접촉 오류를 감추지 않는다.
