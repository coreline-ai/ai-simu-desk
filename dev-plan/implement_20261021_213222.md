작성 일시: `2026-10-21 21:32:22 KST`

## 개발 목적

완료한 로컬 활동 v8을 기준으로, 3명 동시 이동과 5명 착석 회의를 별도 후보 공간에서 단계적으로 구현하기 위한 계획이다. **이 문서는 7번의 개발 계획이며 다인 활동 구현은 아직 시작하지 않았다.**

## 개발 범위

- 실제 가구·몸·통로 여유를 측정한 5인 회의 공간 샘플과 좌석/컵 지지점.
- 새 프로필에서 최대 3명 이동, 공유 통로 양보·공정한 대기·좌석 점유와 안전한 복귀.
- 3~5명 회의의 도착 확인·발언 순서·경청·시선·손 지지·업무 우선 중단.
- 기존 v8/공간 v6 비교·실패 복구·로컬 제품 적용 전의 독립 검수.

## 제외 범위

- 외부 DB/AI/서비스·유료 기능·원격 배포, 사용자 데이터 삭제/자동 정리, 커밋·푸시.
- 5명 초과 캐릭터·무제한 자유 이동·전면 물리 엔진·립싱크/음성·새 캐릭터 제작.
- DB에 아바타 위치/좌석을 실시간 공유하는 멀티플레이 기능. 현재 공동 공간의 실제 업무/권한 계약은 유지한다.

## 기준과 설계 결정

- 현재는 캐릭터 5명·최대 2명 이동·소파/회의 각 2석이다. 20계정 부하 검수는 캐릭터 20명 이동을 뜻하지 않는다.
- 기존 제품 기본값은 v8/공간 v6로 보존한다. 신규 후보는 활동 v9/공간 v7을 별도로 결합하고, 해당 후보에서만 이동 3명·회의 최대 5명을 허용한다.
- 정원 숫자만 늘리지 않는다. 현재 전체 경로를 미리 점유하는 셀 예약과 정지 인물의 점유 반경은 새 공간에서도 검증해야 한다.
- 공간은 초기 검토 범위 11.6~12.8m × 9.2~10m를 참고하되, 최종 크기·책상 위치·회의 테이블/외곽 통로는 측정 후 확정한다. 기존 가구를 늘려 겹치게 배치하지 않는다.
- 실제 업무가 도착하면 회의를 안전하게 끝내고 전원이 복귀하는 동작을 먼저 구현한다. 서버 업무/답변 저장은 시각적 복귀를 기다리지 않는다.
- 접촉 코어 후보는 실제 피부 관통량이 아니다. v8에서 남긴 후보를 좁은 메시 검사/근접 화면으로 확인하고, 실제 문제를 방치한 채 밀도를 늘리지 않는다.

## 공통 진행 규칙

- 각 Phase의 자체 테스트를 완료한 뒤 다음 구현으로 진행한다. 발견 이슈는 해당 Phase에서 수정하고 기록한다.
- 기존 API·Three.js·표준 라이브러리를 우선 사용한다. 새로운 경로/상태 프레임워크나 의존성은 검증된 필요 없이 추가하지 않는다.
- 책임은 공간 데이터·이동 예약·회의 진행·동작 표현으로만 나눈다. 서버 실행과 시각 상태를 혼합하지 않는다.
- 기존 기본값/비교 경로/모델·105개 클립·소품 단일 소유권·일시 정지/폐기를 보존한다.
- 실측이 실패하면 경로/가구 배치를 수정한다. 정원·몸 반경·성능 합격 기준을 조용히 낮추지 않는다.
- 최종 소스 고정 후 실제 시간 검수를 한다. 이전 v8 기록·빠른 시뮬레이션·중단된 측정으로 신규 합격을 대신하지 않는다.
- 실물 모바일/발열·GPU 메모리는 실제 근거가 생기기 전까지 미완료 상태를 유지한다.

## QA 관점

- [ ] 사람 수·슬롯 수·소품 수가 다른 입력, 중복 인물/좌석·이미 업무 중인 인물을 거절한다.
- [ ] 3명 이동을 표시에만 늘리거나 몸/통로 반경을 줄여 합격시키지 않는다.
- [ ] 마지막 도착자의 실패·대기자의 업무·중간 취소·공간 폐기에서 예약과 컵이 남지 않는다.
- [ ] 발/손의 지지점·실제 메시와 관절 도달을 확인하고 자유 손의 완충으로 소품 접촉 오차를 숨기지 않는다.
- [ ] 관절 속도 검사에서 몸 전체의 이동/회전과 관절 자체의 튐을 구분한다.
- [ ] 모션 축소 브라우저의 업무 검사·가속 계산·실제 시간·실물 기기 결과를 구별한다.
- [ ] UI에 보이는 동료의 움직임과 실제 업무·승인·저장 결과의 상태가 어긋나지 않는다.

## 첫 실행 범위

첫 구현은 **나라를 포함한 3명의 독립 경로와 5석의 정적 지지 검증**으로 제한한다. 이 두 선행 검증이 통과하기 전에는 5인 대화 연출이나 제품 기본값 교체로 진행하지 않는다.
