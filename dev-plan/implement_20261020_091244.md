# implement_20261020_091244.md

작성 일시: `2026-10-20 09:12:44 KST`

이 문서는 캐릭터 동작과 Fake AI 개선 제안의 개발 범위를 정리한다. 사용자 승인에 따라 Phase 1→2→3 순서로 구현·검증을 완료했다. 기존 미커밋 변경과 사용자 데이터를 보존했다.

## 개발 목적
나라·준의 업무 상태를 동작으로 읽을 수 있게 하고, 외부 AI 호출 없이 요청의 조건을 반영하는 실제 산출물을 제공한다.

## 개발 범위
- 기존 미터 단위 사무실·앉은 캐릭터·계층형 노드 애니메이션을 확장한다.
- 대기/사고/타이핑/승인 대기/완료/실패 표현, 자연스러운 눈 깜빡임과 동료별 리듬을 추가한다.
- Fake AI를 의도·산출물·조건 추출 → 유형별 결과 작성 → 규칙 검증의 순수 함수로 개선한다.
- 후속 단계에서 사용자가 선택한 이전 결과를 바탕으로 수정하고 나라→준으로 넘기는 기능을 추가한다.
- 로컬 실행과 Vercel 요청 기반 진행이 같은 생성 계약과 결과를 사용하게 한다.

## 제외 범위
- 실제 LLM·인터넷 검색·외부 AI API·유료 서비스·모델 학습.
- 보행·의자에서 일어나기·립싱크·전신 스키닝·물리 기반 손 IK.
- 실행 중인 서비스나 데이터를 바꾸는 자동 도구 실행.
- 외부 공개 배포. 후속 사용자 요청에 따라 구현·검증 결과와 문서를 main에 커밋·푸시한다.

## 현재 코드에서 확인한 한계
- 실제 GLB에는 인물당 idle 5.6초/typing 0.8초의 두 클립만 있다. 얼굴·몸통·팔의 노드 애니메이션이며 전신 인체 리그가 아니다.
- 제품의 teamSceneState는 running만 typing, 나머지는 idle로 매핑한다. 서버의 분석/작성 stage가 동작에 반영되지 않는다.
- 선택·과거 기록 변경이 현재 업무 담당자를 바꾸지 않는 경계와 정지 시 클립 시간 보존은 이미 구현되어 있다.
- composeFakeAnswer는 정규식의 첫 분기로 6가지 유형 하나를 선택한다. 계획 키워드가 개발 키워드보다 먼저 검사된다.
- 키워드 최대 6개와 요청 앞 160자를 표시하지만, 실제 조건 기반 일정·글 초안·원문 요약을 작성하지 않는다.
- AgentJob에는 현재 요청만 있고 이전 업무 결과나 명시적인 후속 요청 연결이 없다.
- 원격판은 조회 시 답변을 재계산한다. 문맥을 읽을 때마다 바꾸거나 무작위 문구를 넣으면 스트리밍 결과가 바뀔 위험이 있다.

## Phase 2. 조건을 반영하는 Fake AI v2
### 목표
요청을 반복하거나 작업 방법만 안내하던 응답을, 조건에 맞는 일정표·체크리스트·문구 초안으로 바꾼다.

### 설계
하나의 의도 분기 대신 domain(개발/기획/글쓰기), deliverable(계획/비교/요약/초안), constraints(기간/인원/예산/플랫폼/제외 조건)를 별도로 추출한다. 예를 들어 ‘1명이 2주 안에 무료로 로그인 기능 개발 계획’은 개발 분야의 계획 산출물로 처리한다.

- 기존 fake-ai.ts는 스트리밍·취소·장애 재현 어댑터로 유지한다.
- 순수 분석 함수는 지원하는 표현과 조건을 추출하고, 불확실하거나 충돌한 조건은 가정/확인 필요로 구분한다.
- 유형별 작성 함수는 일정표·API/DB 체크리스트·제목/본문 초안·원문에서 뽑은 요약 등 실제 산출물을 만든다.
- 검증 함수는 기간 합계·요청한 항목 수·금지 조건·빈 결과·길이를 검사한다. 충족하지 못한 조건을 성공했다고 표시하지 않는다.
- 사전 지식은 프로젝트에서 승인한 버전 고정 자료만 사용한다. 자료 식별자 없이 ‘검색했다’, ‘최신 정보다’라고 표시하지 않는다.
- 범용 자유 추론은 제공하지 않는다. 지원 유형 밖의 요청은 필요한 정보를 묻거나 가능한 결과 형식을 안내한다.

### 구현 태스크
- [x] 순수 분석/유형별 작성/검증을 최소 책임 단위로 분리한다. 다중 의도 점수와 명시적인 조건 객체를 사용한다.
- [x] 나라: 대상 사용자·목표·우선순위·문구 초안, 준: 구현 단계·API/DB·완료 테스트 중심으로 결과를 달리 만든다.
- [x] 정보가 충분하면 결과를 바로 작성하고, 필수 입력이 없으면 핵심 질문 1~2개만 출력한다. ‘요약’ 요청에 원문이 없으면 요약 방법을 결과처럼 내놓지 않는다.
- [x] 숫자·단위와 부정 조건을 보존한다. 2주를 임의로 10근무일로 단정하거나, 무료 조건에 유료 도구를 넣지 않는다.
- [x] 공통 엔진이 구조화된 analyze/compose/review phase와 결과를 반환하도록 하고 로컬/원격 실행 경로에서 재사용한다.
- [x] 실행별 엔진 버전·입력 조건·완성 결과/생성 스냅샷을 한 번 고정하여 진행 중 조회나 배포 후 재조회에서 내용이 바뀌지 않게 한다. 이미 생성한 스트림의 앞부분을 다시 쓰지 않는다.
- [x] 기본 답변은 약 2,000자 이하, 상세 답변은 4,000자 이하를 목표로 한다. 기존 최대 16,000자·30초 실행 제한과 취소를 유지한다.
### 자체 테스트
- [x] 고정 평가 입력 30개를 만든다: 유형별 6개, 복합 요청·조건 10개, 부족/충돌/지원 외 요청 6개, 역할 차이·수정 준비 4개, 권한·원격 재조회 4개.
- [x] 기간/예산/인원/항목 수 반영, 요약 원문 근거, 제목·본문 존재 등 결과에 맞는 검사를 한다.
- [x] 동일 입력·스냅샷·엔진 버전이면 로컬/원격에서 동일한 최종 결과와 스트림 접두부가 생성되는지 검사한다.
- [x] 네트워크 호출 차단 상태에서 생성하고 정상/승인/취소/장애/재시도와 전체 회귀를 통과한다.
### 이슈 및 수정
- [x] 30개 고정 평가와 실행/재조회 검증 등 관련 35개 테스트 통과. 실제 웹에서 2주/1명/무료/3개 항목을 표시하고 답변을 저장했다. migration 006으로 실행별 생성 결과·엔진 버전과 구조화 phase를 저장하며 승인 전 결과 본문 노출을 차단했다. 시간 구간에 소수 일차가 나타난 문제는 정수 일차 배분으로 수정했다.
### 완료 조건

먼저 Phase 1의 thinking/waiting/success 동작을 추가해 상태 차이를 보이게 한다. 이어서 Phase 2의 조건 추출과 ‘개발 계획/문구 초안’ 두 산출물부터 완성하고 지원 유형을 확장한다. Phase 3의 문맥·인계는 기본 산출물 평가를 통과한 뒤 진행한다. 캐릭터의 다음 변화는 동작 가짓수, Fake AI의 다음 변화는 답변의 구체성으로 각각 확인한다.
