# AI Simu Desk

작은 3D 사무실에서 동료에게 업무를 맡기고 결과를 모으는 제품입니다. 로컬 실행과 요청 기반 PostgreSQL 호환 실행 구성을 제공합니다. 현재 개발 범위는 **외부 DB·결제·업그레이드 없이 로컬만**입니다. **로그인과 DB 저장은 실제 기능이며, 답변은 규칙 기반 Fake AI가 만듭니다.** 외부 모델·검색 API·API 키를 사용하지 않습니다.

## 로컬 제품 실행

검증 환경은 macOS와 Node.js 22.22.2입니다. 프로젝트 루트에서 실행합니다.

```sh
npm ci
npm run setup:local
npm run build:product
npm start
```

[나의 스튜디오 열기](http://127.0.0.1:4180/). `계정 만들기`에서 이름·이메일 형식의 식별자·12자 이상 비밀번호를 입력합니다. 로그인 하단의 ‘게스트로 바로 시작하기’로 가입 없이 체험할 수도 있습니다. 동시 유효 게스트 세션은 최대 5개이며 각자 다른 개인 공간을 사용합니다. 게스트 세션은 2시간으로 고정되며 로그아웃/만료로 자리를 반환합니다. 다시 새 게스트로 입장하면 이전 공간을 재할당하지 않습니다. 이메일 확인 메일은 발송하지 않습니다.

- Better Auth 이메일/비밀번호 로그인·로그아웃, 서버 DB 세션, 개인·공동 작업 공간.
- 1회용 초대 코드로 공동 공간에 참여하고 소유자·업무 참여·보기 전용 권한으로 나라·준의 업무·승인·답변을 함께 확인합니다.
- 공동 공간 참여자의 온라인·오프라인, 온라인 인원과 최근 입장·퇴장 시각을 공유합니다. 같은 계정의 여러 탭은 한 명으로 집계합니다.
- Drizzle + 파일 영속 PGlite(Postgres WASM)에 계정·업무·설정·댓글·알림 저장. 로컬과 배포용 진입점은 동일한 요청 기반 Fake AI·DB presence와 SQL 마이그레이션을 사용합니다.
- 나라(기획)·소라(디자인)·준(개발)·민(QA)·레오(정리) 5명. 기간·인원·무료 조건을 반영하는 규칙 기반 Fake AI와 분석·작성·검토 단계.
- [5명 사무실 집중보기](http://127.0.0.1:4180/#office)에서 ‘5명 협업 시연 시작’으로 기획→디자인→개발→QA→정리의 전달 요약과 역할별 결과를 한 실행에 저장합니다. 실제 외부 AI 5개를 병렬 실행하는 기능은 아닙니다.
- 완료 결과의 3줄 요약·표 변환, 원본 버전/조건 보존과 나라↔준 수동 인계. 인계는 승인 후 실행합니다.
- 기획/개발/문구 템플릿, 소유자가 저장하는 목표·대상·기술·제외 조건과 업무에 넣기.
- 전체 기록의 요청·답변 검색, 담당/상태 필터와 20개씩 페이지 조회, 저장한 원본과 수정/인계 결과의 줄 비교.
- 업무별 댓글, 승인 요청·완료·실패·다른 참여자 댓글의 앱 내 알림과 읽음.
- 승인·거절·취소·장애 재현·재시도와 최근 실행 20개 조회. 새로고침·재로그인·서버 재시작 후 기록 복원.
- 준비·작성·검토 동작 구분, 전달 손짓·수신 끄덕임과 공개된 결과의 인계 카드. 5명별 반복 속도·휴지 구간을 보정하고, 전신·부분 스키닝과 생활 동작에 공간 품질 v6를 적용합니다. 활동 초기화 실패 시 원본 v6, 에셋 실패 시 원본 v5와 v4 순서로 복구합니다. [동작·인계 검증](docs/team-handoff-qa.md).
- 9.6×7.6m로 확장한 실제 GLB 사무실과 5개 독립 작업 공간, 독립 대기·사고·타이핑·승인 대기·완료·실패 동작과 눈 깜빡임. 동료 클릭·키보드 선택, 함께 보기·동료별 초점을 지원합니다. 선택이나 과거 기록을 바꿔도 실행 담당자는 유지됩니다.

`시뮬레이션 설정 → 일시적 장애 재현`으로 실패·재시도를 살펴볼 수 있습니다. 예시 요청은 `첫 화면의 핵심 메시지와 구성을 제안해 줘`, `로그인 API와 DB 연결 설계를 검토해 줘`입니다. 답변은 조건 추출과 유형별 작성 규칙으로 생성되며 실제 언어 모델의 추론이나 검색 결과가 아닙니다. 실행별 답변과 생성 버전을 고정해 재조회·재시도에서도 내용이 바뀌지 않습니다.

현재 외부 DB 연결 없이 설정은 서버 전용 `.env.local`, 데이터는 `.data/studio`에 저장합니다. `DATABASE_URL`이 설정된 경우에는 같은 PostgreSQL 어댑터/마이그레이션 경로로 연결할 수 있지만 이번 작업에서는 외부 연결을 수행하지 않았습니다. 설정 생성 명령은 기존 파일을 보존합니다. 비밀값·DB·백업을 공유하거나 정적 서버로 제공하지 마세요. 제품 서버는 `product/dist`의 공개 파일만 제공합니다. 개발 중에는 `npm run dev:product`를 사용할 수 있으며 프런트엔드 변경 후 `npm run build:product`를 다시 실행합니다.

로컬판은 loopback HTTP·단일 프로세스로 동작합니다. 원격판은 아래 Vercel Functions·PostgreSQL 구성을 사용합니다. OAuth·이메일 인증·비밀번호 재설정 메일·MFA, 공동 편집, 실제 LLM 연결은 포함하지 않습니다.

## 기존 배포 준비 코드 (현재 작업은 로컬 전용)

사용자 결정에 따라 외부 제공 DB를 연결하지 않습니다. 현재 Vercel 자체 Postgres 신규 제공은 종료되었으므로 ‘Vercel 직접 제공 PostgreSQL’ 연결 완료를 주장하지 않습니다. 아래는 기존에 준비한 배포 경로이며 이번 작업에서 생성·연결·배포하지 않았습니다. [공식 제공 방식](https://vercel.com/docs/postgres).

**Docker 없이 Vercel Hobby + Neon Free PostgreSQL**로 배포하도록 구성했습니다. 기본 `vercel.app` HTTPS 주소를 사용하므로 별도 도메인 설정은 뒤로 미룰 수 있습니다. [배포 순서·필요 환경변수](docs/vercel-deployment.md)를 따르세요. 실제 Vercel/Neon 계정 연결과 공개 배포는 아직 수행하지 않았습니다.

- Node.js 22의 `api/index.ts` 하나로 API를 처리하며 정적 UI는 CDN에서 제공합니다.
- 세션·업무·접속 상태는 PostgreSQL에서 공유하여 Function 인스턴스가 바뀌어도 이어집니다. Secure 쿠키·고정 HTTPS origin·DB 로그인 요청 제한을 사용합니다.
- 원격 Fake AI는 저장된 시각에 따라 조회 때 진행을 반영합니다. 상시 작업자나 유료 큐/Cron을 사용하지 않습니다. 화면을 모두 닫으면 다음 조회 때 진행이 반영됩니다.
- 원격 동기화는 2.5초 한 요청, 숨김 탭 30초입니다. 무료 한도에는 호출·CPU·메모리·DB 사용량이 함께 적용되며 무제한 무료를 보장하지 않습니다.

```sh
npm run build:vercel     # 배포용 UI와 함수 진입점의 로컬 빌드 검사
npm run vercel-build    # Vercel의 실제 빌드: 서버 환경변수 필요, DB 마이그레이션 포함
```

[원격 QA 결과](docs/remote-qa.md): 자동 51개 + 실제 PostgreSQL/TLS 통합 4개 통과. 실제 클라우드 배포·실물 원격 기기 검증은 계정 연결 후 남은 단계입니다. 기존 로컬 DB는 원격으로 자동 이전하지 않습니다.

## 공동 공간 사용

`공동 공간 만들기` → `참여자 · 초대와 권한 관리`에서 초대 코드 발급 → 다른 계정의 `초대 코드로 참여` 순서로 사용합니다. 코드는 1시간·1회용이며 재발급하면 이전 미사용 코드는 폐기됩니다. 소유자는 전체 업무와 권한을, 업무 참여자는 자신의 요청을 제어하고 보기 전용은 상태·결과를 확인합니다. [사용법과 여러 계정 검증](docs/collaboration-qa.md)을 참고하세요.

공간당 최대 20명, 소유자당 공동 공간 5개, 공간당 활성 실행 하나입니다. 참여자 목록은 권한을 가진 계정이며 온라인 인원은 현재 그 공간을 열고 연결된 계정입니다. 로컬판과 배포용 코드는 2.5초/숨김 30초의 통합 sync 주기로 확인합니다(브라우저 절전 시 지연될 수 있습니다). 마지막 탭의 공간 이동·로그아웃·종료 요청이 도착하면 퇴장하며, 종료 요청이 유실되면 마지막 heartbeat 후 75초에 만료됩니다. 연결 실패 시 현재 화면은 `확인 중`으로 전환합니다.

접속 상태와 최근 20건의 출입은 임시 기록입니다. 로컬판과 배포용 코드 모두 DB에 저장하고 임대 만료/재접속으로 갱신합니다. 서버 재시작 시 메모리에만 의존하지 않습니다. 업무·승인·답변은 기존 DB에 보존합니다. [접속 상태 판정과 검증 결과](docs/presence-qa.md)를 참고하세요.

## 백업과 복구

먼저 제품 서버를 `Ctrl+C`로 정상 종료합니다. 다른 프로세스가 DB를 사용 중이면 백업 명령이 거절됩니다.

```sh
npm run db:backup
# 출력된 실제 백업 파일 경로를 사용하고, 새 대상 폴더를 지정합니다.
npm run db:restore -- .data/backups/실제-파일명.tar.gz .data/restored-studio
```

기존 데이터 폴더를 덮어쓰지 않습니다. 복구 DB를 사용하려면 서버가 꺼진 상태에서 `.env.local`의 `STUDIO_DATA_DIR`을 새 경로로 변경하고 `npm start`로 실행합니다. 기존 `.env.local`의 인증 비밀값도 보관해야 기존 세션을 이어갈 수 있습니다. 백업에는 계정·세션·업무 데이터가 포함되므로 비공개로 보관합니다.

## 고품질 전신 스튜디오 v5

[다섯 동료의 새 공간](http://127.0.0.1:4180/demos/studio-v5/)에서 가입 없이 전체 환경·역할별 소품·낮/저녁·화질 3단계와 생활 동작을 검수합니다. 현재 제품 기본은 공간 품질 v6이며, 이 페이지는 원본 v5를 보존합니다. 쉬는 동료는 동시에 한 명만 옆 통로를 이용하고, 업무를 받으면 복귀·착석 후 작업 자세로 전환합니다. 서버의 실제 업무 실행은 지연시키지 않습니다.

전체 에셋은 로컬 소스에서 생성하며 5명×21종=105개 클립을 GLB로 내보냅니다. `npm run build:office`는 v5 모델/검수 페이지를 갱신하고, `npm run build:product`는 제품과 모든 데모를 빌드합니다. [전체 v5 검수 기록](docs/visual-upgrade-qa.md).

### 나라 1명 선행 샘플

[새 3D 에셋 랩 열기](http://127.0.0.1:4180/demos/visual-upgrade/) — 로그인 없이 나라 한 명의 기립·접지 보행·기지개·복귀와 창가 작업 공간을 확인합니다. 기존 v4와 같은 카메라·광원으로 나란히 비교하고, 정지 자세 검수·일시정지·회전·확대를 사용할 수 있습니다. 이 페이지는 한 명의 선행 비교 샘플이며, 현재 다섯 명 제품의 v5 확장과 구분합니다.

`npm run build:product`에 샘플 빌드가 포함됩니다. 실행 중 샘플만 재생성하려면 `npm run build:sample` 후 브라우저를 새로고침합니다. 외부 모델/텍스처 없이 로컬 기하·PNG·관절/부분 스키닝으로 재현합니다. [샘플 검수 기록](docs/nara-sample-qa.md), [진행 계획](dev-plan/implement_20261020_123957.md).

## 기존 시각 데모

2.5D와 3D 파일럿은 이전 모의 업무 흐름을 보존합니다. 이 두 화면의 기록은 탭 메모리에만 있으며 새로고침하면 초기화됩니다.

```sh
npm run serve:demos
```

- [2.5D 단일 파일 데모](http://127.0.0.1:4173/demo/preview.html): 오피스 이미지와 접지·크기·방향을 보정한 투명 직원 아틀라스.
- [실제 3D 파일럿](http://127.0.0.1:4173/pilot-3d/): 자체 제작 GLB, 같은 카메라·광원, 회전·확대·화질·오류 대체 화면.

서버는 `demo/`, `pilot-3d/`, `docs/`만 제공합니다. 프로젝트 루트를 일반 정적 서버로 제공하지 않습니다. 소스 수정 후 `npm run build:preview`, `npm run build:3d`로 각각 갱신합니다. 모델은 계층형 노드 애니메이션이며 인체 스키닝·보행 리그가 아닙니다. 에셋 출처·치수는 각 `assets/manifest.json`에 기록했습니다.
