# 캐릭터 개성 v13 구현·검수 기록

> 이 문서는 해당 구현 당시의 검수 기록입니다. 이후 사용자 요청으로 main 전달 문서/커밋을 준비했습니다. 최신 배포 인계는 [HANDOFF](../HANDOFF.md)와 [전달 검증](local-release-20261024.md)을 따릅니다.

검수: 2026-10-24, 로컬 macOS / 실제 Ego Chromium WebGL 화면. 로컬 Fake AI 서버이며 외부 배포·Blender 연결·Git 커밋/푸시는 하지 않았다.

## 구현

- 공통 선행: 손바닥과 가늘어지는 다섯 손가락을 하나의 연결된 피부 메시로 생성하고 16개 뼈로 스키닝. 손끝 완충·손톱·room/close LOD 추가. 기존 실제 소품 접촉 좌표, 두 마디 수치 솔버와 길이는 유지했다. 해부학적 독립 3관절 IK나 손 전체 충돌 시스템으로 표현하지 않는다.
- 1차 전담 3개: 나라 / 소라 / 준. 2차 전담 2개: 민 / 레오. 담당자는 각자 디렉터리와 테스트만 수정했고 리드가 공유 코드 통합·브라우저 검수했다.
- 각 3변형, 서로 다른 9.6~11.2초 작업 길이·긴 멈춤·시선·몸통·자유 손가락·완료 반응·책상 지지 소품. 기존 실제 컵·종이 소유권/반납 우선.
- 기본 자동 하루 시작은 나라→소라→준→민→레오 약 0.8초 간격. 첫 대표 변형은 0/2/0/1/1로 분산. 명시적 역할 시연 변형 선택과 반복 재현 보존.
- v13은 개인별 체험과 제품 주 런타임에 적용. 기존 비교 v11과 `?version=12` 경로 보존. `선택 동료 손 가까이` 카메라 추가.

| 전담 | 구별되는 3변형 |
|---|---|
| 나라 | 세 줄 우선순위 메모 / 긴 보드 사고 후 결론 / 카드 두 개 비교·연결 |
| 소라 | S 곡선 후 전체 구도 확인 / 팔레트 비교·수정 / 선을 짚고 열린 손 설명 |
| 준 | 검지·중지 교대 입력과 긴 읽기 / 마우스 탐색·스크롤·디버깅 / 코드 행을 가리키고 동료 확인 |
| 민 | 항목·화면 대조 / 불일치 재검토·수정 / 최종 확인과 두 체크 |
| 레오 | 두 차례 정렬 후 확인 / 문장·행을 따라 긴 읽기 / 분류 탭 비교·문서 위치 선택 |

## 실제 화면 확인

스크린샷은 저장소의 무시되는 `.data/personality-qa/`에 있다. 원경과 동일 손 근접 카메라로 확인했다. 정적 사진만으로 동작 검사를 대신하지 않고 실제 재생→중단→다른 역할 시작도 수행했다.

- `five-personalities-room.png`: 다섯 캐릭터 정상 표시, 거대 피부 구체 없음.
- `<id>-hands-v0.png`: 다섯 명 각각의 연속 손 외피, 펜/키보드/종이와 손가락 확인. 나라 필기, 소라 펜 띄움, 준 입력 후 손 정지, 민 화면 대조, 레오 정렬 확인.
- `intro-<id>-hands.png`: 최종 기본 자동 하루의 개별 대표 동작. 실제 7.82초에서 나라 세 번째 줄 기록 / 소라 열린 손 설명 / 준 화면 읽기 / 민 불일치 재검토 / 레오 행 읽기. 시작 시각 0 / .80 / 1.62 / 2.42 / 3.22초, violations 빈 배열.
- `hand-cup-first.png`, `hand-cup-side.png`: 컵 잡기와 팔 이동 중 손 외피를 두 시점에서 확인. 초기 시점에는 모니터/팔이 컵을 가리므로 시점을 돌려 분리해서 확인했다.

추가 UI 검수 결과와 최종 검사 수치는 아래에 기록한다.

## 발견·수정

모듈 범위 출력 검사만 통과했던 나라/소라의 큰 필기 경로와 뒤로 젖힘 조합에서 실제 팔 도달 오류(.485~.486m)를 발견했다. 각 전담이 실제 fixture 3변형 전체 회귀를 추가하고 가까운 종이/태블릿 영역과 몸통 자세를 재설계했다. 공용 IK나 접촉 좌표를 허위 축소하지 않았다. 수정 후 최소 팔 여유: 나라 27.5/34.2/30.5mm, 소라 30.4/11.0/14.0mm.

## 한계

- 고품질 Blender 조형/애니메이터 제작 에셋이 아니라 코드 생성 스타일라이즈드 손이다. 극단 근접의 손가락 교차·전체 피부 충돌을 완전히 해결했다고 주장하지 않는다.
- 레오의 실제 양손 종이 지지, 물리적 트레이 삽입, 준의 실제 키 입력/마우스 기능은 구현 범위가 아니다. 시각 업무 동작이며 실제 업무 시간·DB를 조작하지 않는다.
- 검수는 이 로컬 데스크톱 브라우저 기준이다. 실물 모바일/저사양 GPU 성능이나 전 저장소 테스트 완료를 주장하지 않는다.

## 추가 실제 UI 검수

- 준 변형2와 나라 변형1을 각각 새 역할로 재생하고 멈춰 근접 관찰했다(`jun-index-point-v2.png`, `nara-reflection-v1.png`). 정리→반납→다른 역할 시작에서 violations는 비어 있었다.
- 나라의 사고 동작 중 실제 업무 버튼을 눌러 즉시 `replace / owner=hand / returning=true`로 전환함을 확인했다. 업무 종료·활동 정리 후 다섯 역할이 `idle / owner=desk`로 돌아왔다.
- 검지 설명을 실제 화면으로 보니 idle 말림과 authored curl이 누적되어 검지가 충분히 펴지지 않았다. 공용 자유 손 경로에서 authored curl을 절대값으로 처리하도록 보정했다. 실제 펜·컵·종이 접촉 블렌드에는 적용하지 않는다. 편 검지의 실제 길이 >68mm, 접힌 약지와 차이 >15mm인 회귀 테스트를 추가했다. 후속 확인은 `jun-index-point-verified.png`에 기록한다.

## 검사 실행

- 관련 회귀 묶음 **76/76 통과**: 5개 전담, 런타임 통합, 연속 손, 초기 정지, 페이지 자동 재생/반복, 렌더러 해제, 기존 역할·안경·실제 업무·공유 프레임.
- 마지막 자유 손 보정 후 손/런타임 **9/9 추가 검사 통과**(위 묶음과 중복되는 검사 포함, 합산하지 않음).
- `npm run typecheck`, `npm run check:boundaries`, `npm run check`, `npm run check:product`, `git diff --check` 통과. 전체 저장소 `npm test`를 실행했다고 주장하지 않는다.
- 최종 빌드 게시: `1792802125923-f9274044-3fc4-45be-bd47-1cf746b3ac6f`. 최종 서버는 이 릴리스를 핀한 프로세스로 재시작했다. 소스 에셋은 빌드의 해시 보존 검사 통과.
- 빌드의 기존 GLTFExporter material 권고 경고가 출력되지만 빌드·게시 자체는 성공했다.

## 동일 조건 렌더 비용 비교

실제 브라우저 동일 1344×730 CSS 캔버스, DPR 1.5, 기본 화질, zoom 1, `play=0` 초기 자세에서 관찰했다. 그림자 패스 포함 renderer 카운터이며 FPS/VRAM 벤치마크가 아니다. 원본은 `.data/personality-qa/render-cost.json`.

| 카메라 | v12 삼각형 / draw calls | v13 삼각형 / draw calls |
|---|---:|---:|
| 전체 공간 | 773,350 / 1,097 | 797,062 / 1,093 |
| 동일 나라 손 근접 | 558,268 / 718 | 654,556 / 696 |

텍스처 카운터 45→55(스켈레톤 bone texture 포함). 삼각형 비용은 원경 약 +3.1%, 근접 약 +17.2%다. 원경/근접 LOD는 적용했지만 이 결과로 모든 장치에서 성능 향상이나 60fps를 보장하지 않는다. `baseline-v12-first-frame.png`에서도 기존 경로의 정상 첫 프레임을 확인했다.

## 최종 실행 확인

최종 보정 후 실제 화면에서 준의 검지 69.16mm, 약지 51.95mm를 확인했고 후속 근접 이미지에서도 펴진 검지를 확인했다. 페이지 열기와 새로고침 모두 버튼 없이 v13 자동 하루가 시작됐다. 8.17초 관찰에서 paused=false, 5명 분산 시작, 0/2/0/1/1 변형, violations 빈 배열 (`.data/personality-qa/autoplay.json`, `final-autoplay-room.png`). 검수용 브라우저는 정리했고 서버는 `http://127.0.0.1:4180`에서 실행 중이다.
