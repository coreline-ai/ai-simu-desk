검증일: 2026-10-20 KST. 사용자 요청에 따라 Docker VPS 방식 대신 Vercel Hobby + 외부 PostgreSQL 배포 구성을 구현했다.

로컬 PostgreSQL·HTTPS 통합 성공을 실제 클라우드 배포 완료로 표시하지 않는다. 배포 가이드는 [Vercel 안내](vercel-deployment.md), 공개 증거는 [HTTPS 검사 결과](../product/evidence/remote/https-qa.json)다.

## 확인한 경계

- **DB 전환:** PGlite와 PostgreSQL이 같은 Drizzle 스키마/저장 규칙을 사용한다. 마이그레이션 체크섬과 advisory transaction lock으로 동시 적용을 보호했다. 기존 마이그레이션은 변경하지 않고 004/005를 추가했다.
- **다중 인스턴스:** 두 DB 풀의 동시 공간 생성은 하나로 수렴한다. 1회용 초대의 동시 소비와 동시 업무 시작은 한 요청만 성공한다. 서로 다른 앱에서 동일 Run/답변을 확인했다.
- **접속 상태:** PostgreSQL 저장 기반 다중 탭/계정 집계, 한 탭만 퇴장, 마지막 연결 퇴장, 종료 탭 재사용 409, 정확한 75초 만료, 새 서비스 인스턴스에서 상태 유지, 로그아웃/세션 폐기/멤버 철회, 최근 20건 제한을 검사했다.
- **업무 진행:** 승인 전 대기 유지, 새 앱 인스턴스에서 진행 재개, 긴 조회 공백 뒤 정확한 답변, 실패/재시도/취소·출력 제한을 검사했다. 시뮬레이션이므로 독립 상시 작업자로 실행하지 않는다.
- **HTTPS 인증:** 실제 TLS 서버와 두 독립 쿠키 세션으로 요청했다. 테스트 CA를 명시적으로 신뢰하고, 신뢰하지 않은 CA는 거절됨을 확인했다. 쿠키 Secure·HttpOnly와 같은 세션의 다른 인스턴스 접근을 확인했다.
- **원격 보안:** 위조 Host/Origin 거절, 환경 설정 누락·HTTP 원격 origin·URL 경로/사용자정보 거절, 공유 DB의 로그인 시도 제한 429를 확인했다. `.env.local`/`.data`/서버 소스/검증 자료 HTTP 경로는 404다.
- **무료 계정 대응:** 30초 이내 요청 함수, 상시 루프/Cron/유료 큐 없음, 2.5초 통합 sync/숨김 30초, 외부 Neon Free 연결 안내. 사용량에 따른 무제한 무료 운영 보장은 하지 않는다.

## 발견과 보정

1. Docker daemon이 없어 npm의 별도 플랫폼용 PostgreSQL 바이너리를 비공개 `.data/remote-tools`에 설치하고 격리한 합성 DB를 만들었다. 공유 메모리가 필요한 초기화/실행은 샌드박스 권한으로 실행했다. 이 바이너리와 인증서 키는 제품 의존성/커밋에 넣지 않았다.
2. 실제 HTTPS 시험의 Hono Node 어댑터에서 글로벌 Request 교체를 꺼 둔 시험 설정이 body-limit와 충돌했다. 제품과 같은 기본 어댑터 설정으로 보정하여 네트워크 검사를 통과했다. API를 우회하거나 TLS 검증을 끄지 않았다.
3. 서버리스 메모리 인증 제한은 인스턴스 간 합산되지 않으므로 Better Auth의 DB 저장 제한과 005 테이블을 적용하고 실제 교차 인스턴스 11번째 실패 로그인에서 429를 확인했다.
4. 자기 연결이 75초 뒤 다시 들어오면 다른 관찰자가 없어도 만료 퇴장과 재입장을 둘 다 남기도록 DB 집계에서 처리했다. 업무 cursor/권한 revision은 접속 갱신으로 바꾸지 않는다.

## 남은 배포 단계

Vercel 프로젝트 + Neon Free 연결, 서버 전용 DATABASE_URL/secret/HTTPS origin 설정, 실제 플랫폼 배포, 두 실물 기기에서 같은 URL로 공동 공간 참여·업무·온라인 상태 확인이 남아 있다. 도메인 DNS 변경은 필요하지 않다. 실행 절차와 무료 한도는 배포 문서에 기록했다.
