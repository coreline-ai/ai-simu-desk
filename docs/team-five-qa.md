# 5명 협업 스튜디오 검증

2026-10-20 KST. 사용자 확인에 따라 게스트 접속자 수와 별개로 나라·소라·준·민·레오 캐릭터 5명을 제품에 추가했다. 외부 DB/LLM/유료 업그레이드는 사용하지 않았다.

## 적용
- 제품용 사무실 v3는 9.6×7.6m, 기존 7.2×5.6m 대비 바닥 면적 약 81% 증가. 뒤 3자리/앞 2자리, 휴게 가구를 재배치했다. 동일 책상 0.74m/좌면 0.45m/앉은 캐릭터 크기를 유지한다.
- 나라(기획)→소라(디자인)→준(개발)→민(QA)→레오(정리). 옷 색·머리·안경/묶은 머리·이름표·역할 카드로 구분한다. 전체 보기/각자 가까이/집중 보기/움직임 정지·재생을 지원한다. 좁은 화면 이름표는 이름만 표시하고 역할은 카드/접근성 이름에 유지한다.
- 선택적 includeTeam으로 독립적인 35개 애니메이션(5명×7클립)을 export한다. v3는 436 메시/142,128 삼각형/약 3.94MiB. 기존 v1/v2 아티팩트는 보존한다.
- 5명 협업 시연 버튼은 예제 프로젝트의 실제 로컬 DB 실행을 만든다. 하나의 요청/승인/취소/재시도/답변으로 관리하며 5개 역할의 규칙 기반 산출물을 고정한다. 각 후속 역할은 앞 역할의 결과와 조건을 context로 받아 전달 요약을 포함한다. 개별 업무 담당자도 5명 중 선택할 수 있다.
- 화면에서 현재 역할은 작성, 앞 역할은 전달 후 검토, 다음 역할은 자료·기준 준비로 표현한다. 마지막에는 5명 완료 반응 후 대기로 돌아간다. 캐릭터 초점/움직임 정지는 업무 자체를 바꾸지 않는다.
- 다섯 실제 AI가 병렬로 실행되는 것은 아니다. 기존 Fake AI의 한 실행 안에서 역할별 결과와 준비/작성/검토를 표현한다. 승인 전 본문은 노출하지 않으며 저장된 시각에 따라 요청 시 진행을 반영한다.

## 자동 검증
- 전체 회귀 107개 통과. 타입/구문/의존성 경계/제품 및 배포용 로컬 빌드 통과.
- 실제 기기 내부 PostgreSQL/TLS/HTTPS 통합 5개 통과. 두 앱 인스턴스가 5명 협업을 실행·조회하고 모든 역할의 완료 결과를 공유하는 검사 포함. 시험 DB는 검증 후 종료했다.
- GLB 실제 재수입: 선택 ID 5개/노드 이름 고유/54개 지지점 접지 및 방 내부/작업 공간 간 비중첩/휴게 가구와 비중첩/35개 클립/독립 동작/가구 고정.
- 카메라의 모든 방 모서리가 1280/640, 390/440, 319/440 화면비에서 프레임 안에 위치한다.
- 역할별 출력과 순서·전달 정보, 승인 전 본문 미노출, 중복 키, 보기 전용 거절, DB 재생성 후 같은 결과, 취소/재시도 답변 고정, 기존 나라·준 개별 업무 회귀.
- 기존 DB를 정상 종료한 뒤 `.data/backups/pre-team-five-20261020`에 비공개 백업하고 migration 011만 추가 적용했다. 게스트 최대 5명 정책은 유지한다.

## 화면 검수에서 보정
- GLTFLoader가 만드는 scene 래퍼 대신 실제 사무실 노드의 자리 메타데이터를 읽도록 수정했다. 이름표와 신규 동료 개별 카메라 초점이 실제 자리와 맞는다.
- 오래된 모델의 고정 좌표가 부동소수점 연산으로 달라지지 않도록 기존 분기를 보존하여 v2 파일/명세 변경을 없앴다.
- 긴 협업 전달 요약을 자를 때 생략 부호를 표시하고 규칙 버전 3.1로 고정한다. 이전 고정 답변은 보존한다.
- 넓어진 장면은 기본 전체 너비이며, 좁은 화면은 짧은 이름표/개별 초점으로 식별을 돕는다.

## 실제 웹 확인
첫 협업에서 5개 역할 결과 저장과 각각 완료 표시를 확인했다. 서버 진행 중 실제 액션은 나라/소라/준 thinking + 민/레오 typing으로 분리되어 있었다. 움직임 정지 상태에서 소라로 카메라를 바꿔도 animationTime 89.91이 유지되고, 다시 재생한 뒤 전체 보기로 복귀했다.

## 최종 웹 검증
- 1280px에서 전체 5개 자리·이름표·역할 카드와 협업 진행을 확인했다. 실제 DOM 액션이 5개 thinking에서 5개 typing으로 전환됐고 animationTime은 103.65→105.53으로 증가했다. 다음 역할 작성 중 앞 역할은 검토 동작으로 분리된다.
- 390px와 319px에서 문서 너비가 각각 390/319px, 5개 이름표가 모두 표시되고 이름표 겹침 0개. 작은 화면의 역할은 카드와 접근성 이름에 유지한다.
- 새로고침 후 5개 역할 결과와 이전 기록이 보존된다. 브라우저 콘솔 경고/오류 0개.
- 사무실만 보는 집중 모드 `/#office`와 업무 화면 복귀를 제공한다. 이 모드에서도 협업 시연·다섯 개별 초점·정지/재생을 조작할 수 있다. 실제 과거 실행의 답변/승인을 보려면 업무 화면으로 돌아간다.

## 모바일 상단 메뉴 후속 보정
- 사용자 제보의 298px 화면에서 상단 메뉴가 축소되어 ‘전체 둘러보기’가 115px 높이, ‘로그아웃’이 84px 높이로 세로 줄바꿈되는 현상을 재현했다. 이전 가로 넘침 검사만으로는 이 문제를 발견하지 못했다.
- 600px 이하에서는 로고·AI 표시와 메뉴를 두 행으로 배치하고, 메뉴 글자의 줄바꿈·축소를 막았다. 메뉴 글자를 12px로 키우고 링크·로그아웃의 터치 높이를 44px로 통일했다. 집중 모드의 고정 헤더 높이도 모바일에서 해제했다.
- 실제 웹에서 280/298/319/390/600/601/768/1280px 집중 보기와 298/390/601/1280px 일반 업무 화면을 확인했다. 메뉴는 한 줄로 표시되고 모두 헤더 내부에 있으며 문서 가로 넘침이 없다. 브라우저 경고·오류 0개, 제품 빌드 통과.
