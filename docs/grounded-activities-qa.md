# 접지와 교감 활동 v8 · 남은 1~6번 구현·검수

2026-10-21 · main `da7ac4f` 이후 로컬 작업. [개발 계획](../dev-plan/implement_20261021_191000.md)의 **1~6번 로컬 구현·검수와 제품 반영을 완료**했다. 기존 v7을 보존하고 활동 v8을 기본 적용했다. 실물 모바일은 사용자의 연결 불가 답변에 따라 미완료다. 외부 서비스/DB/AI·실제 사용자 데이터 정리·커밋/푸시는 수행하지 않았다.

## 완료한 검수

최종 팔꿈치 보정 소스의 전체 자동 **260개 통과/실패 0**를 확인했다. 이전 259개 및 중단 기록은 아래와 같이 구분한다.

- 보정 전 전체 자동 **259개 통과/실패 0**. 이후 책상 팔 보정의 전환에서 200.4mm/25ms 팔꿈치 튐을 추가 재현해 최종 소스를 보정했다. 해당 근거는 `before-elbow-continuity/`에 보존하며 최종 합격으로 세지 않는다. 타입·의존 경계·구문 검사, 후보 전체 안전 빌드 통과. 이후 운영 도구의 schema/sequence·기준 날짜 경계를 집중 재검수했다.
- 접촉 거리의 교차/평행/퇴화/분리와 강제 몸 겹침 검출. v7에는 새 진단·보정을 적용하지 않는다.
- 5명 실제 신발 메시의 바닥 최저점·다리 도달·도중 업무/복귀, 경로/정지/곡선의 지지점 미끄러짐 검사 통과.
- 10짝×양 좌석 순서의 회의 손/팔꿈치 연속성·표면 간격·컵 우선권·예약/소품 회수, 5명 중간 업무와 정확한 정지/재개 통과.
- 최종 소스의 1,800초 빠른 혼합에서 전원 역할 3변주·컵·회의·소파·창가·방문·업무/완료와 회수 통과. 실제 시간 검수와 구분한다.
- 실제 브라우저 후보 실패의 9개 복구 경로·최종 원본 v4의 두 번 WebGL 복원 및 실제 v8 회의 지지 중 WebGL 복원, 버전 엔트리·canvas 1·오류 0 통과.
- 현재 제품의 320~1440px 8개 폭·키보드·모션 축소, v8 비교 화면의 320/768px에서 넘침 0·canvas 1 확인.
- 문서 수신 중 실제 5역할 Fake AI 업무가 먼저 저장되고, 소품 정리·복귀 후 완료 cue와 저장 결과 재조회가 유지됨을 확인.
- 임시 파일 DB에서 실제 CLI의 사용 중 잠금/백업 없음/잘못된 revision 거절, 정리 전후 계정·답변·댓글 보존과 원래 raw 백업의 격리 복구 지문 일치 통과.

최종 후보의 새 임시 경로에서 잠금파일 의존성 오프라인 설치·설정 0600/보존·전체 빌드·동일 JS/GLB·5개 브라우저 협업·16개 공개 경로/비공개 차단·백업 복구 후 세션/답변/댓글 보존도 통과했다. 브라우저 5개 업무 검수는 모션 축소 상태로 수행해 실제 동작 장시간 검수와 구분한다.

## 접촉 진단의 해석

같은 seed의 600초/50ms 시뮬레이션에서 겹침 후보가 있던 표본은 v7 11,951/12,000 → v8 476/12,000으로 감소했다. 깊은 후보 표본은 11,950 → 166였다. **남은 후보는 0이 아니다.** 기존 단독 소파 자세의 팔/몸 근접과 이동 전환·테이블 AABB 모서리 등을 추가 시각 검토 대상으로 기록한다. 최대 대체 체적 겹침은 v7 70.3mm·v8 64.5mm로, 잔여 후보는 추가 근접 검토 대상으로 남긴다.

캡슐/AABB는 피부/소매/원형 테이블을 정확히 표현하지 않는 단순 대체 체적이다. 팔 캡슐은 옷의 외곽 전체를 감싼 경계가 아니라 관절을 잇는 코어이므로 얇은 옷 관통을 놓칠 수도 있다. 양수 겹침은 좁은 범위의 메시 검사와 근접 화면으로 확인할 후보이며, 숫자를 실제 피부 관통량으로 단정하지 않는다. 진단값을 0으로 숨기거나 이 결과로 전체 비관통·압력·마찰·GPU 메모리를 보장하지 않는다. 손바닥 목표의 지지 간격은 1.5mm다.

## 데이터 보존

[보관 정책](local-retention-policy.md)에 따라 수동 정리는 7일 이상 지난 만료 세션·인증 임시값·접속 임대 행으로 제한한다. 전체 public 테이블의 내용/스키마/시퀀스 상태 지문과 cutoff를 묶어 검토 토큰을 만든다. raw 백업의 격리 복구본을 검증하고 트랜잭션 안에서 현재 DB와 보호 이력을 다시 확인한다. 사용자·공간·업무·답변·이벤트·댓글·알림·설정은 삭제하지 않는다. 실제 사용자 DB에 정리를 적용하지 않았다.

## 근거·재현

근거는 `product/evidence/grounded-activities/`에 저장한다. `checks.json`은 최종 17개 근거의 지문·실제 경과·소스 불변·합격 범위와 실물 미완료를 집계한다. 앱 SHA-256은 준비된 후보·4191 검수·4180 제품에서 `b0177274a8ac9ce25f1d3535ab367d193ed21858c0f9d594180b817574b489fa`로 같고, 서버 SHA-256은 `d97d0e86aead1c922b3266bfa18d4027a05703290112ef7fd7b303653db74662`다. 공간 모델은 이전 제품과 동일하다. 실제 모바일은 [체크리스트](mobile-device-checklist.md)에 미완료로 기록한다.

정상 종료한 기존 DB의 비공개 백업 후 관리된 release로 교체하고 4180을 재시작했다. 공개 16경로·29개 JS/CSS 해시·비공개 4경로 차단과 실제 브라우저의 v8 선택/재생·canvas 1·오류 0을 확인했다. 최종 release 식별자와 HTTP 결과는 `activation.json`에 남긴다. 기존 사용자 DB에 합성 부하나 수동 정리를 적용하지 않았다.
