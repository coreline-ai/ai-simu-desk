## 데이터와 게스트 정책

백업은 migration을 적용하지 않고 원래 스키마/내용을 보존한다. 정상 종료·단일 DB 잠금·비공개 아카이브·새 경로 복구 원칙을 유지한다. 실제 DB 백업의 격리 복구본과 모든 public 테이블의 행/스키마 지문 일치를 확인했으며 실제 DB를 복구본으로 덮어쓰지 않았다.

신규 공동 공간 소유자는 일반 계정이며 게스트는 초대로 member/viewer로 참여한다. 게스트는 최대 5개의 독립 세션/2시간을 유지한다. 일반 owner의 오프라인은 공간 종료 사유가 아니다. 기존 게스트 owner의 유효 세션이 사라지면 다음 정상 sync/권한 조회에서 공간을 읽기 전용으로 보존하고 대기/실행 중 업무와 승인을 취소 정리한다. 저장된 결과/구성원은 유지한다.

복구 CLI는 서버 정상 종료·백업·현재 revision·기존 일반 계정 member 지정을 요구한다. 자동 승격/삭제·HTTP 소유권 복구는 없다. 실제 사용자 공간의 소유권은 이전하지 않았다. 저장 용량·만료 데이터의 보관은 [관측·보관 정책](local-retention-policy.md)을 따른다.

성능 측정 중 별도의 혼합/생활 검수 루프가 실행 중이었음을 근거에 기록했다. 고유 geometry 수는 13개(6.5%) 늘었고 textures 수는 같았다. draw calls/triangles 예산은 통과했으며 이 수치로 GPU 메모리를 추정하지 않는다. 초기 바이트는 로컬 응답의 리소스 본문 합계이며 인터넷 전송 속도나 압축 효과를 의미하지 않는다.

첫 실제 혼합 30분은 오류/회수는 정상이지만 레오의 방문·typing 커버리지가 부족해 불합격으로 보존했다. 기존 활동을 마친 동료의 방문 기회를 예약 자원을 잡지 않는 대기로 보존하고, 실제 업무가 오면 즉시 양보하도록 보정한 뒤 실제 10분/30분을 다시 통과했다. 원래 짧은 업무 프로필의 seed17 반복/29 변화도 별도 회귀했다. 빠른 API 업무는 시각 전달/복귀를 기다리지 않고 완료하며 복귀 후 완료 cue를 재생하는 실제 API 검사를 통과했다.

짧은 runner smoke·빠른 시뮬레이션·미완료/중단 측정은 실제 60분 합격 근거에 넣지 않는다. 첫 메모리 시도는 추가 검색 보정으로 중단했고, 다음 시도는 검수 스크립트의 로그아웃 선택자 오기로 중단했다. 제품 동작 오류와 runner 오류를 구분해 보존하며, 올바른 로그인/로그아웃 전체 주기 smoke 통과 후 최종 고정 소스로 실제 60분을 완료했다. 성능의 첫 canvas 판정도 크기 배열/개수의 runner 계약 오류를 보정하고 전체 6회를 다시 측정했다.

60분 종료 후 4개 로그아웃 표본의 JS heap은 6.58→6.92→7.11→7.28MiB였고 이벤트 리스너는 매번 86개였다. 모델 버퍼에 해당하는 backing storage도 매번 약 0.84MiB로 회수됐으며 GPU 메모리 수치로 해석하지 않는다. 활성/회수 heap 변화는 미리 정한 20% 또는 8MiB 기준을 통과했다. 이 결과는 해당 1시간/자료 수 조건에서의 관측이며 누수 0이나 실물 기기 성능을 단정하지 않는다.

## 화면·전체 제품 검수

늦은 A 응답이 선택한 B를 덮는 기록 선택, sync가 프로젝트 저장 중 잠금을 푸는 문제, 오래된 설정이 새 버전을 덮는 문제, OS 모션 축소와 버튼 표시 불일치를 보정했다. 추가로 오래된 sync가 읽음 알림/새 댓글을 되돌리는 문제와 늦은 검색 오류/세션 종료 후 검색 잠금을 재현·보정했다. 댓글은 불변 항목으로 병합하고 공간/선택/변경 세대로 과거 응답을 폐기한다. 409/네트워크 오류는 작성 중 설정을 보존한다.

새 임시 경로에서 잠금파일 의존성 설치→설정 생성/0600/기존 설정 보존→전체 빌드→서버 시작→14개 공개 URL 200/비공개 URL 404를 확인했다. 캐시가 없던 최초 항목은 고정된 동일 버전만 공식 레지스트리에서 받았고 최종 재검수는 오프라인 설치로 통과했다. 외부 애플리케이션 서비스/DB/AI에는 연결하지 않았다.

후행 정적 미들웨어가 API 진단의 경로를 `*`로 가리는 경우도 재현했다. 진단은 마지막으로 실행된 등록 경로를 사용하며 강제 오류/비밀값 제외 회귀를 통과했다.

일반 owner와 게스트 member/viewer 4명, 총 5개 실제 브라우저에서 프로젝트·템플릿→member의 5역할 업무→owner 승인→동일 결과→텍스트 댓글→수정/비교→기록 검색→강제 승인 수동 인계→취소/실패/재시도→읽음 알림 유지→철회/로그아웃을 검수했다. 이 UI 검수는 모션 축소로 진행했으며 실제 움직임 검수와 구분한다. 별도 HTTP 부하 검사는 5게스트/6번째 거절·다중 탭 1명 집계·세션 만료/철회를 확인했다.

합성 DB를 정상 종료하고 raw 백업/새 경로 복구해 20개 public 테이블 행 수를 대조했다. 같은 컴파일 서버를 복구 DB로 재시작해 기존 owner 쿠키·원래 답변·댓글이 보존됐음을 확인했다.

## 실제 제품 적용

기존 서버를 정상 종료하고 새 비공개 백업을 만들었다. 격리 복구본과 원본의 20개 public 테이블 전체 행·컬럼/인덱스/제약조건 지문을 대조해 일치했다. raw 용량 보고도 완료했으며 실제 DB 복구/소유권 이전은 수행하지 않았다.

`npm run build:product`가 전체 검증 후 클라이언트/서버의 단일 포인터를 전환했다. 서버가 정지된 상태에서 실제 이전 정상본으로 되돌린 파일 트리 지문이 변경 전과 일치함을 확인하고 새 산출물로 재적용했다. 실제 4180의 공개 경로 14개 200·JS/CSS 버전 엔트리 26개 해시/200·정적 재검증·익명 API 401/no-store/요청 ID·비공개 파일 404와 로컬 PGlite/Fake AI를 확인했다.

`product/dist`, `server/dist`는 디렉터리와 심볼릭 링크 모두 Git 추적에서 제외한다. 실행 중 서버는 시작한 release의 정적 경로를 고정하며 문서 갱신도 검증된 전체 산출물로 교체한다.

## 재현 명령

```sh
npm run typecheck
npm run check:boundaries
npm run check
npm run check:product
npm test
npm run build:prepare
npm run qa:server
```

별도 터미널에서 다음 runner를 실행한다. QA 서버는 실제 `.env.local`을 읽지 않으며 외부 DB/API에 연결하지 않는다. 종료하면 임시 DB를 정리한다. 설치된 Playwright 또는 기존 번들 런타임을 사용하며 다른 환경은 `STUDIO_PLAYWRIGHT_PATH`, `STUDIO_CHROME_PATH`를 지정한다.

```sh
node scripts/qa/ui-races.mjs
node scripts/qa/guest-collaboration.mjs
node scripts/qa/fallback.mjs
node scripts/qa/activity-soak.mjs continuous
node scripts/qa/activity-soak.mjs mixed
node scripts/qa/lifecycle.mjs --smoke
node scripts/qa/lifecycle.mjs
node scripts/qa/performance.mjs
node scripts/qa/assets-and-layout.mjs
node --import tsx scripts/qa/collaboration-load.ts
node --import tsx scripts/qa/compiled-smoke.ts .data/build-releases/<prepared-id>
```

실제 시간 runner는 UI/동작 소스를 고정한 채 실행한다. 실제 10분/30분은 종료 후 전원 회수까지 합격해야 하며 표본·손 진단·필수 성공 전달·소스 불변/오류 0을 확인한다. 60분은 전후 구간의 강제 GC 후 JS heap을 같은 조건으로 비교하고 로그아웃 canvas 0을 확인한다. JS heap은 GPU 메모리가 아니다. 중단/누락 상태는 합격으로 저장하지 않는다.

빌드 실패 주입은 `node scripts/qa/build-failure.mjs`로 현재 정상 서버를 유지한 채 수행한다. 준비/적용/직전본 복구와 재시작 절차는 [README](../README.md#안전한-로컬-빌드-교체)에 기록했다. 관리되는 산출물에 개별 데모 빌더로 쓰지 않는다. 공개 HTML의 JS/CSS URL은 내용 해시로 구분하고 정적 응답은 `no-cache`로 재검증한다. 버전 쿼리가 붙은 URL에서도 7단계 fallback과 최종 v4 복원 검사를 통과했다.

- 실물 모바일 터치·발열 20분·실제 OS 백그라운드/설정, GPU 메모리·20명 성능은 미측정이다. 에뮬레이션/JS heap으로 완료 처리하지 않으며 최종 판정 범위는 데스크톱 로컬 안정화다.
