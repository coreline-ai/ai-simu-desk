# 로컬 데이터 관측·보관

기본 정책은 보존이다. 업무·답변·프로젝트 설정·댓글·알림·게스트 이력은 자동 삭제하지 않는다. 게스트의 2시간 세션 만료와 공간 접근 정책은 데이터 삭제와 별개다. presence의 임대/정리 규칙도 업무 이력을 삭제하지 않는다.

서버를 정상 종료한 뒤 `npm run db:report`로 현재 스키마를 그대로 열어 테이블별 행 수·논리/디스크 용량·활성/비활성 게스트 수를 확인한다. 이 명령은 migration이나 정리를 실행하지 않으며 내용·계정 ID·토큰을 출력하지 않는다. 사용 중인 DB는 잠금으로 거절한다. 보고서의 테이블 이름은 로컬 스키마 이름이다.

용량이 커지면 먼저 비공개 백업을 만들고 격리 경로에 복구해 행 수/업무 연결을 확인한다. 삭제 여부·기간·대상은 운영자가 별도로 결정한다. 만료 게스트 계정·읽은 알림·이벤트를 나이만으로 삭제하면 공유 답변/감사·동기화 연결을 손상할 수 있으므로 해당 데이터의 삭제 명령은 제공하지 않는다.

v8 후속 작업에서 추가한 `db:retention`은 **만료된 세션·인증 임시값·접속 임대 행** 세 테이블만 수동 정리한다. 계정·공간·업무·답변·이벤트·댓글·알림·설정은 모두 보존한다. 자동 실행/HTTP API는 없다. 기본 기준은 30일 전이며 7일보다 최근인 기준은 거절한다. 실제 데이터에 정리를 적용하는 결정은 운영자가 별도로 한다. 이번 개발 검수는 합성 임시 DB에서만 적용한다.

서버를 정상 종료한 뒤 다음 순서로 진행한다. `--before`에는 preview에서 확인한 것과 **동일한 ISO 날짜**를 사용한다.

```sh
npm run db:backup
npm run db:retention -- preview --before 2026-09-21T00:00:00.000Z
# counts/total을 검토한 뒤 출력된 revision과 방금 만든 실제 백업 경로를 사용
npm run db:retention -- apply --before 2026-09-21T00:00:00.000Z --revision <검토한해시> --backup <비공개백업파일>
npm run db:report
```

`revision`은 전체 public 테이블 내용·스키마·시퀀스 상태의 지문과 기준 날짜를 묶는다. apply는 raw 백업을 메모리에 격리 복구해 같은 내용인지 확인하고, 트랜잭션 안에서 현재 DB를 다시 대조한다. 백업 불일치·기준 변경·데이터 변경·DB 사용 중·백업 없음은 거절한다. 세 테이블 외의 내용이 바뀌면 롤백한다. 정리된 임시 기록을 복구하려면 원래 백업을 새 경로에 복구하고 기존 복구 절차를 따른다. 정리는 DB 파일 압축/디스크 공간 즉시 반환을 보장하지 않는다.

2026-10-21의 격리 운영 검수는 합성 완료 기록 1,000개를 먼저 만든 후 5세션으로 실제 3,611초 동안 업무·댓글을 60건씩 추가했다. 7,482요청의 오류는 0이었고 원래 결과의 지문은 같았다. 이 조건에서 논리 용량은 약 1.27MB, 디스크도 약 1.27MB 증가했다. 별도의 20계정 sync/검색 부하와 최대 5게스트 제한도 검수했다. 이 결과는 해당 합성 작업량의 관측값이며 장기 용량 예측이나 실제 사용자 데이터 정리 결과를 뜻하지 않는다. [검수 근거와 측정 조건](grounded-activities-qa.md)을 참고한다.

요청 진단은 서버의 500 오류에 한해 요청 UUID, HTTP 메서드, 등록된 경로 패턴, 상태·오류 종류·소요 시간을 남긴다. 응답의 `X-Request-ID` 및 500 응답의 `requestId`로 연결한다. 쿠키/Authorization·URL 쿼리·초대 코드·업무/댓글 본문·예외 메시지/stack은 기록하지 않는다. 진단 실패는 요청 실패로 전파하지 않는다. 파일 로그 자동 보관은 없으며 터미널 로그의 저장/폐기는 로컬 운영자가 관리한다.
