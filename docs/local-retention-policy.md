# 로컬 데이터 관측·보관

기본 정책은 보존이다. 업무·답변·프로젝트 설정·댓글·알림·게스트 이력은 자동 삭제하지 않는다. 게스트의 2시간 세션 만료와 공간 접근 정책은 데이터 삭제와 별개다. presence의 임대/정리 규칙도 업무 이력을 삭제하지 않는다.

서버를 정상 종료한 뒤 `npm run db:report`로 현재 스키마를 그대로 열어 테이블별 행 수·논리/디스크 용량·활성/비활성 게스트 수를 확인한다. 이 명령은 migration이나 정리를 실행하지 않으며 내용·계정 ID·토큰을 출력하지 않는다. 사용 중인 DB는 잠금으로 거절한다. 보고서의 테이블 이름은 로컬 스키마 이름이다.

용량이 커지면 먼저 비공개 백업을 만들고 격리 경로에 복구해 행 수/업무 연결을 확인한다. 삭제 여부·기간·대상은 운영자가 별도로 결정한다. 만료 게스트·읽은 알림·이벤트를 나이만으로 삭제하면 공유 답변/감사·동기화 연결을 손상할 수 있으므로, 이번 안정화에는 삭제 명령을 제공하지 않는다.

요청 진단은 서버의 500 오류에 한해 요청 UUID, HTTP 메서드, 등록된 경로 패턴, 상태·오류 종류·소요 시간을 남긴다. 응답의 `X-Request-ID` 및 500 응답의 `requestId`로 연결한다. 쿠키/Authorization·URL 쿼리·초대 코드·업무/댓글 본문·예외 메시지/stack은 기록하지 않는다. 진단 실패는 요청 실패로 전파하지 않는다. 파일 로그 자동 보관은 없으며 터미널 로그의 저장/폐기는 로컬 운영자가 관리한다.
