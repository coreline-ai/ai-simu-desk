# 나라 전신·창가 작업 공간 샘플 검수

검수일: 2026-10-20 KST. 이 문서는 선행 샘플의 이력이며, 이후 전체 5명 적용 결과는 [v5 전체 QA](visual-upgrade-qa.md)를 참조한다. 범위는 최종 계획의 **Phase 0~1, 나라 1명 선행 샘플**이다. 기존 다섯 명 협업 제품·DB·Fake AI·v4 모델은 유지한다. 외부 에셋·서비스·DB 연결·유료 도구를 사용하지 않았다.

## 실행과 비교

- [로컬 에셋 랩](http://127.0.0.1:4180/demos/visual-upgrade/), [전체 둘러보기](http://127.0.0.1:4180/start).
- `npm run build:product` → `npm start`. 실행 중 샘플만 갱신: `npm run build:sample` 후 새로고침.
- `나란히 비교 / 새로운 3D / 기존 v4`를 전환한다. 동일한 OrthographicCamera·광원·ACES exposure 1.03·sRGB 출력으로 렌더한다. 기존 v4 원본 GLB에서 나라의 `Workspace`를 분리했으며, 전체 방과 한 자리를 성능상 동등하다고 해석하지 않는다.
- 원본 2.5D 이미지는 화면 아래 분위기 기준으로 표시한다. 실제 3D 렌더와 혼동하지 않는다.
- `정지 자세 검수`에서 타이핑, 기립, 보행 중간, 양팔 최대 높이, 착석을 고정한다. 시간 슬라이더를 움직이면 정지하며 재생으로 이어간다. 드래그·줌·정면·전체·근접 구도를 지원한다.
- 22초 시연: 발 당겨 딛기·의자 빼기 → 기립 → 회전 → 1.35m 옆 통로 보행 → 기지개 → 휴식 → 복귀·착석. 반복 여부를 선택한다. 실제 업무 생성/저장과 연결하지 않는다.

노드 관절을 먼저 검증한 뒤, 관절이 둥근 부품처럼 드러나는 외형을 보정하기 위해 소매·바지에만 부분 스키닝을 적용했다. 몸 전체를 새 물리/애니메이션 엔진으로 교체하지 않았다. GLB에 `nara_typing / stand_up / standing / turn / walk / stretch / rest / sit_down` 8개 클립을 실제 저장한다. 런타임은 같은 포즈 생성 소스를 사용해 발 접지와 이동을 계산한다. 클립에 ActorRoot 이동 트랙을 중복 저장하지 않는다.

손·발·머리 anchor와 metre/+Y/floor 0 계약, 바닥 접지, 5자리 단순 장애물 진출입을 검사했다. 발의 디딤 구간과 들기/마지막 착지 보간을 구분한다. 관절 연속성 검사는 120Hz 샘플에서 프레임당 5.5cm 이상 튀는 머리/손/발을 검출한다. 새 업무 복귀 요청은 현재 위치를 보존해 발을 정리하고 회전·복귀·착석한 뒤 작업 자세로 돌아간다. 시연 중 서버 업무를 지연시키는 기능은 없다.

## 발견 이슈와 수정

1. 기존 나라 자리 이름은 `NaraWorkspace`가 아닌 `Workspace`였다. 원본 GLB 바인딩에 맞췄다.
2. GLTFLoader의 기본 ImageBitmap 경로는 blob 이미지를 fetch하여 현재 CSP connect-src와 맞지 않았다. **CSP를 바꾸지 않고** 이미지용 TextureLoader 경로를 사용했다. 필수 map이 빠지거나 디코딩되지 않으면 성공으로 표시하지 않는다. 실제 브라우저에서 56개 메시의 PNG 디코딩을 확인했다. 색상 map은 sRGB, roughness는 NoColorSpace를 재수입 검사한다.
3. 초기 작업 공간 파일이 9.2MiB였다. 같은 구·반복 키보드/가구 형상을 공유하고 불필요한 세분화를 줄였다. 최종 파일과 해시는 `product/assets/nara-sample-manifest.json`이 기준이다.
4. 귀환 방향에서 좌우 발이 뒤바뀌던 계산을 수정했다. 기립/보행 경계의 팔 스윙·골반 높이와 마지막 발 내리기를 보간했다. 16개 중단 시점에서 복귀의 위치 연속성과 다리 도달 범위를 검사했다.
5. 손의 회전된 AABB는 실제 표면보다 크게 잡힌다. 타이핑 관통 검사는 실제 변환된 메시 정점으로 검사하고, 손바닥이 책상 아래로 들어가지 않게 팔꿈치 각도를 보정했다.
6. GLB에 Three.js의 cast/receive shadow 플래그가 저장되는 것으로 가정하지 않고, 기존 v4/신규 양쪽에 같은 동적 그림자 플래그를 복원했다. 이전 제품 렌더러의 동작과 맞췄다.
7. 화면 비율별 전체 모델 bounds를 맞춰 모바일에서 바닥/창·팔이 잘리지 않게 했다. 현재 Three.js의 PCFShadowMap을 사용해 제거된 shadow 타입 경고도 없앴다.

## 시각 판정

최종 비교·근접·기지개·보행 캡처에 대한 내부 시각 판정이다. 1~5점의 주관적 검수이며 외부 전문가 인증이나 객관적 화질 계측은 아니다.

| 항목 | 샘플 판정 | 근거 / 다음 한계 |
|---|---:|---|
| 형상·실루엣 | 4 | 헤어 덩어리/가닥·귀/귀걸이·손가락·신발/끈·의자/책상 모서리와 소품 구분. 사실적인 인체/머리카락 렌더 수준은 아님 |
| 재질·UV | 4 | 내장 나뭇결, 천, 테라조, 금속/도자기 구별. 256² 소형 텍스처이며 근접 고해상도 직조/normal map은 후속 |
| 빛·접촉 | 4 | 같은 광원에서 움직이는 발과 가구의 실제 그림자 확인, 바닥에 고정된 사람 그림자 없음. 면광원급 부드러운 간접광은 후속 |
| 캐릭터·관절 연결 | 4 | 부분 스키닝으로 소매·바지 연결, 최대 기지개·기립·걷기·착석의 분리 없음. 손가락 개별 리깅/천 시뮬레이션은 없음 |
| 배치·식별 | 4 | 앞·옆 통로/의자 후퇴·발/책상 크기 정합, 한 자리와 나라 식별. 전체 다섯 자리 상세 환경은 미구현 |

샘플 범위에서 관통/분리/필수 텍스처 누락의 중대 결함은 수정 후 발견하지 못했다. 이 판정은 **다음 제작 단계로 진행할 샘플 기준**이며, 105개 동작·전체 공간·실제 모바일 기기의 완료 판정이 아니다.

## 자동 검사

- 전체 자동 검사 124개 통과. 마지막 의상/보행 보정 후 해당 샘플 검사 10개 재실행 통과.
- `npm run typecheck`, `npm run check:product`, `npm run check:boundaries`, `npm run build:product` 통과.
- 기존 v4 파일 해시 보존. 신규 GLB 재로드 시 skin 4개·관절·anchor·8개 클립·색상/거칠기 map 확인. Node의 이미지 디코더만 대체하며 실제 PNG 디코딩은 브라우저에서 별도 검수했다.
- 30/60Hz 전 구간의 다리 길이·바닥 침투, 120Hz 접지 고정/관절 연속성, 16개 시점 중단 복귀, 기존 5자리 그레이박스 통로, 책상/좌판/손 접촉 검사.
- 390×844 뷰포트에서 가로 넘침 0, 메뉴·전체 전신/창가 구도 확인. 물리 모바일 기기 시험과 구별한다.

## 성능과 예산

신규 샘플 실측: 3회 각각 2,249 frames, p50 13.30ms / p95 14.30ms, 13.30ms / 14.30ms, 13.30ms / 14.20ms. 초기 데스크톱 목표 p50≤20ms / p95≤33.3ms 통과. 원본 기록은 `product/evidence/visual-sample/performance-new.txt`. 기존 v4는 같은 1149×508/DPR 1 조건에서 3회 각각 2,249 frames, p50 13.30ms / p95 14.10ms, 13.30ms / 14.30ms, 13.30ms / 14.00ms다. `performance-old.txt`에 보존했다. 현재 브라우저의 약 75Hz 프레임 공급 한계 안에서 두 장면 모두 목표를 통과했으며, GPU 비용이 같다는 뜻은 아니다. 현재 macOS 내장 브라우저, 1280×1000 뷰포트, 캔버스 1149×508 CSS px, 실제 DPR 1. 동일 카메라·광원·노출. 준비 5초 후 프레임 간격 30초×3회 측정한다. 렌더 CPU/GPU 시간 자체나 실제 모바일 GPU 수치로 해석하지 않는다.

샘플 GLB 약 2.32MiB, 264 meshes / 105,900 triangles, 그림자 포함 새 장면 528 draw calls / 211,800 triangles. PNG 5×256² RGBA+밉맵 약 1.67MiB 추정이며 렌더 타깃·그림자·bone texture·브라우저 디코딩 메모리는 별도다. 기존 v4 나라 자리도 그림자를 포함해 110 draw calls / 36,392 triangles다. 새 샘플은 호출 약 4.8배·삼각형 약 5.8배이므로 전체 5명 확장 시 최적화가 필요하다. 기존 v4와 신규 샘플을 동시에 로딩하는 비교 화면은 샘플 단독 다운로드보다 크다. 전체 5명 확장 비용은 아직 실측하지 않았다. 공유 전 단순 5배 약 11.6MiB이므로, 전체 환경 15MiB 예산과 draw call 목표를 다음 단계에서 다시 검사한다.

## 증거와 남은 작업

증거 폴더: `product/evidence/visual-sample/`. `phase0-rig.png`는 최초 노드 리그 검수, `comparison.png`는 같은 조건의 비교, `closeup.png`는 근접, `walking.png` / `stretch.png`는 동작, `mobile.png`는 뷰포트 검수다.

후속: 나머지 네 명과 역할별 작업 키트, 전체 환경, 21종×5명의 클립, 실제 업무 상태/동시 이동 예약 연동, 공통 세 화질·두 조명, 장시간/실제 모바일/OS 동작 줄이기/강제 로드 실패/WebGL 복구. 이번 샘플은 첫 단계 검수용이며 기존 다섯 명 제품 화면의 전면 교체를 수행하지 않았다.
