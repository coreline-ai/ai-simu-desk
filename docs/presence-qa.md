# 공동 공간 온라인·오프라인과 입장·퇴장 검증

후속 업데이트(2026-10-20): Vercel 서버리스용 PostgreSQL 공유 접속 상태와 2.5초 통합 sync를 추가했다. 아래는 로컬 메모리판의 검증 기록이며 원격판은 [원격 QA](remote-qa.md)·[배포 안내](vercel-deployment.md)를 따른다.

검증일: 2026-10-19 KST. Node.js 22.22.2, macOS, 내장 브라우저와 Safari의 서로 다른 실제 로그인 계정으로 확인했다.

## 동작 기준

| 항목 | 구현 |
|---|---|
| 온라인 | 현재 공동 공간에 유효한 접속 임대가 하나 이상 있는 계정. 다른 공간에 로그인해 있는 것과 구분 |
| 다중 탭·세션 | 사용자별 합산. 첫 연결만 입장, 마지막 연결이 끝날 때만 퇴장 |
| 정상 퇴장 | 공간 전환·페이지 종료의 JSON beacon, 인증된 로그아웃의 세션 전체 정리. 전달 실패 시 임대 만료로 보완 |
| 연결 만료 | 마지막 서버 heartbeat부터 75초. 남아 있는 사용자의 다음 조회에서 반영하고 기록 시각은 만료 시각 사용 |
| 갱신 | 기존 업무 조회와 함께 500ms 주기, 숨김 탭 2초. 네트워크/서버 처리 시간과 브라우저 절전의 영향을 받는 조회 방식 |
| 연결 확인 중 | 요청 실패 시 인원·배지를 `확인 중`으로 바꾸고 출입 표시를 비움. 요청 대기는 10초로 제한하여 자동 재시도 가능 |
| 권한 철회 | 모든 heartbeat/leave에서 현재 DB 멤버 인가. 철회된 계정은 404와 기존 개인 공간 복귀. 남은 참여자가 조회하면 철회된 연결 정리 |
| 이력 | 최신 20건, 서버 메모리만 사용. 서버 재시작 또는 10분 이상 조회 없는 비활성 공간 정리 시 초기화 |

개인 공간에는 접속 배지/온라인 인원/출입 이력을 표시하지 않는다. 온라인은 나라·준 AI의 업무 상태와 별개인 사람 계정의 상태다. 절전·강제 종료 때 즉시 오프라인을 보장하지 않으며, 서버는 만료 기준으로 판단한다.

## 구현 경계

- `server/application/presence.ts`: 주입한 시계로 임대·사용자 집계·입장/퇴장·종료 표식 처리. 서버 세션 ID와 탭 ID는 응답에 포함하지 않는다.
- `StudioPort.presenceMembers`와 DB 어댑터: 인가와 현재 멤버 조회를 같은 트랜잭션으로 수행한다. 개인 공간은 거절한다.
- `POST /api/workspaces/:id/presence`, `POST .../presence/leave`: 실제 세션과 기존 same-origin/16KiB 제한 적용. 클라이언트가 보낸 사용자 ID를 신뢰하지 않는다.
- 인증 로그아웃 성공 후 해당 세션의 모든 임대를 종료한다. 진행 중인 첫 heartbeat도 종료 세션 표식으로 차단한다. 다른 로그인 세션의 연결은 유지한다.
- 종료된 탭 ID는 75초 동안 보관해 역순 요청의 재입장을 막는다. 공간당 임대/종료 표식 256개, 세션당 공간 내 16개, 메모리 공간 1,024개로 제한한다. 로그아웃 표식은 75초/최대 4,096개다. 상한은 429로 처리한다.
- `product/src/presence.mjs`: 공간 방문마다 새 탭 ID 발급, 이전 방문 응답 무시, 종료 요청과 확인 중 상태. 업무·멤버 조회 사이에도 공간 세대가 바뀌었는지 재확인한다.
- 접속 갱신은 업무 DB, Run 이벤트 cursor, 초대/권한 revision을 수정하지 않는다. 권한 선택 입력은 접속 변화 때 재생성하지 않는다. DB 마이그레이션과 새 의존성은 없다.

## 자동 검증

`npm test`: **46개 통과**. 기존 37개와 새 서버 6개·제품 접속 수명/표시 3개를 포함한다. 마지막 공간 세대 가드 보완 후 관련 제품 검사 6개도 다시 통과했다. `check`, `check:product`, `typecheck`, `check:boundaries`, `build:product` 통과.

| 새 검사 | 확인한 실패·경계 사례 |
|---|---|
| 사용자 집계 | 같은 계정의 여러 탭/독립 세션, 중복 leave, 하나만 종료, 마지막 세션 로그아웃 |
| 역순·로그아웃 경합 | leave가 첫 heartbeat보다 먼저 도착, 종료 이후 늦은 요청 409, 로그아웃과 대기 중인 첫 요청의 경합 401 |
| 만료·재시작 | TTL 직전/정각, 세션 만료, 재연결 입장, 새로운 서버 인스턴스에서 과거 온라인 미복원 |
| 인가·상한 | 철회·공간 격리, 잘못된 UUID, 탭/공간/프로세스 상한, 오래된 공간 회수, 이력 20건 |
| 실제 인증 HTTP | 비로그인 401, 비회원 404, 출처 403, 잘못된 ID 400, 개인 공간 400, 다른 세션의 같은 탭 ID로 타인 연결 제거 불가 |
| 제품 수명 | A→B→A 늦은 성공/실패 응답 격리, 개인 공간 미등록, 연결 실패 표시와 종료 ID 회전, 비회원 상태를 인원에서 제외 |

실행 중인 제품 서버에서도 `node scripts/presence-smoke.mjs`를 수행했다. 실제 두 쿠키 세션, 다중 탭 중복 이벤트 없음, 종료된 탭 409, 동일 Run 지문과 DB cursor/revision 보존을 확인했다. 스크립트는 `.data`의 비공개 QA 계정과 공간 파일을 사용하며 공개 결과에는 자격증명을 넣지 않는다. [실제 API 결과](../product/evidence/presence/live-smoke.json).

## 실제 브라우저 검증

내장 브라우저의 소유자와 Safari의 보기 전용 계정에서 다음을 확인했다. 브라우저 QA는 실제 화면 검증이며 서버 경계·정확한 만료 시각은 위 가상 시계/HTTP 검사로 검증했다.

- 두 계정 온라인 2명, 이름별 온라인 배지와 입장 시각 일치.
- 소유자 두 번째 탭을 열어도 온라인 수와 입장 이력이 늘지 않음. 하나만 닫아도 남은 탭의 온라인 유지.
- 마지막 공간 연결을 개인 공간으로 바꾸면 상대 화면에 온라인 1명과 퇴장 표시. 재입장하면 2명 복구.
- Safari의 실제 페이지 이동과 로그아웃을 상대 계정에서 오프라인·퇴장/로그아웃 사유로 확인. 재로그인·공동 공간 복귀 성공.
- 접속 갱신 중 소유자가 선택 중인 권한 입력 유지. 테스트 후 원래 보기 전용 값으로 복귀했으며 권한 변경은 제출하지 않음.
- 실제 서버 중단 시 두 배지가 확인 중으로 바뀜. 재시작 후 새 출입 이력과 온라인 상태 자동 복구, 기존 공동 업무 2개와 개인 업무 6개 유지.
- 1280/768/390/319px에서 참여자 패널을 펼친 채 가로 넘침 없음. 기존 두 동료 3D와 업무 화면 표시 유지.

브라우저의 종료 알림은 best effort다. 빠르게 탭을 닫고 다른 탭으로 이동하는 최초 관측에서는 추가 탭의 종료 알림/갱신 시점 때문에 즉시 퇴장을 확인하지 못했다. 임대 유예 이후 남은 연결을 정리한 상태에서 마지막 공간 이동과 명시적 페이지 이동·로그아웃을 재검증했다. 종료 알림 유실을 무기한 온라인으로 남기지 않는 TTL 처리는 가상 시계 검사로도 확인했다.

## 범위와 후속 개발

현재는 loopback HTTP·단일 서버 로컬판이다. WebSocket/SSE·Redis·분산 동시성·20명 실접속 부하 시험·원격 운영 배포는 수행하지 않았다. 인증 세션을 DB에서 직접 폐기한 다른 탭의 접속은 다음 요청/임대 만료로 정리한다. 이미 전달된 과거 화면을 원격으로 회수하는 기능은 없다.

후속 순서는 운영 인증/HTTPS·PostgreSQL 구성 → 공유 접속 저장소와 다중 서버 전달 → 부하·장애 시험이다. 사용자 요청에 따라 Fake AI를 유지한다. [실행 계획](../dev-plan/implement_20261019_201558.md).
