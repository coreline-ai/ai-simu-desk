# 3D 전체 고품질화·다양화 계획 최종 검토 R1

검토일: `2026-10-20 KST` · 기준 코드 `dbe4896` · 대상: [개발 계획](../dev-plan/implement_20261020_123957.md).

## 1. 판정
**초안: 수정 필요 → 필수 수정 반영 후 Phase 0 착수 가능.**

목표는 따뜻한 미니어처 사무실 전체와 다섯 캐릭터를 고품질화하고, 기지개·일어서기·걷기·휴식·복귀까지 연결하는 것이다. 로컬 구현이며 DB/AI 기능 확장은 제외한다. 이번 검토는 설계 검토다. 새 에셋의 외형·보행·성능이 이미 검증됐다는 의미는 아니다.

## 3. 아키텍처·계약 결론
- 서버 스냅샷은 실제 업무의 기준이다. 생활 동작은 그 상태를 읽어 실제 위치/자세를 표현하고 서버 실행을 지연하지 않는다.
- 길찾기가 ActorRoot의 위치/yaw를, 클립이 하위 RigRoot를 소유한다. 앉지 않은 캐릭터에게 타이핑/인계 손짓을 강제로 섞지 않는다. 시선·눈 깜빡임은 제한된 노드만 보정한다.
- 현재 노드 애니메이션을 무조건 폐기할 이유는 없다. 다만 고품질 의상의 어깨/골반 연결은 먼저 시험하고, 실패하면 필요한 몸통/의상만 스키닝한다. 이 결정을 전체 제작 뒤로 미루지 않는다.
- asset registry/manifest는 실제 파일·고유 ID·원본·맵·리그·클립·anchor·bounds를 연결한다. 선언한 에셋/클립 이름 개수와 실제 로드/시각 검수 수를 별도로 집계한다.
- 화질을 바꿔도 신원·클립·위치/시간·선택 상태는 유지한다. 로드 실패는 검증된 v4로 복구하며 v5 활동성 통과로 기록하지 않는다.

## 4. 필수 검증과 인수 증거
| 영역 | 완료를 판단할 증거 |
|---|---|
| 외형 품질 | 고정 구도의 전후 PNG, 가까이 보기/팔 들기/기립의 검수표. 5개 항목 각각 4/5 이상과 중대 결함 0개. 점수는 근거가 있는 시각 판정 |
| 다양성 | 5개 실루엣/역할 키트·식물/의자/재질 목록과 실제 장면. 단순 색/크기 변경은 독립 디자인으로 세지 않음 |
| 리그/입출력 | GLB 재수입으로 UV·재질맵·스킨/관절·105개 필수 이름 바인딩·anchor 확인. 메타데이터 선언만으로 통과하지 않음 |
| 보행 | in-place 클립+실제 이동의 시간별 root/발 좌표와 영상. 초기 기준: 디딤 발 미끄러짐≤2cm, 바닥 침투≤1cm. 회전·서기·앉기 포함 |
| 활동 전환 | 각 필수 동작에서 정지/재개·업무 진입, 인계/실패/취소·경로 실패·공간 전환. 루트 순간이동·늦은 이벤트 재생 없음 |
| 전원 활동 | 대기 중 90초 시연에서 5명 짧은 생활 동작+1명 왕복. 10분 연속 대기에서 5명 모두 스트레칭·1회 이상 왕복, 예약 중복/기아 없음 |
| 성능/수명 | 같은 기기·해상도·DPR에서 5초 워밍업 후 30초×3, p50/p95·전송/로드·메모리 추정. 교체/화질 변경·WebGL 복구 뒤 자원 수 안정 |
| 제품 회귀 | 기존 114개+추가 검사, 4회 협업 인계·권한·게스트·모바일 헤더, actual 4180 브라우저 증거 |

실제 모바일·OS 동작 줄이기·숨김 lifecycle 시험을 수행하지 못하면 해당 항목은 미완료로 남긴다. 데스크톱 뷰포트 축소나 정책 입력 테스트로 기기 시험을 대체 완료하지 않는다. 첫 시연은 검증한 로컬 환경에서 제공할 수 있다.

## 5. 필수 계획 수정 내역
반영 완료: Phase 0 신설, 에셋/동작 인수 목록, 리그·루트·메타데이터·색 관리 계약, 안전 복귀와 활동 공정성, 시각 품질 게이트, 장시간 프레임/자원 검사, v4 복구. 하위 생활 동작 계획의 ‘FPS 10% 저하 제한’은 상위 고품질화 계획의 명시된 측정/예산 기준을 따르도록 정합성을 맞췄다.

계획의 체크박스는 모두 미착수로 유지했다. 이번에는 코드/에셋/DB를 변경하거나 제품 시험을 새로 실행하지 않았다.

## 6. 권장 다음 작업
**나라 1명 전신·보행 기술 샘플 + 한 자리 재질 샘플**을 같은 빌드/로드 경로로 먼저 검증한다. 전신/의상 연결·발 접지·이동 여유·GLB 보존이 통과하면 고품질 한 구역을 완성하고 사무실 전체로 확장한다.

## 공식 기준 대조
- glTF는 노드/스킨·애니메이션 대상과 재질/텍스처 구조를 정의한다. 이 규격을 기준으로 실제 export/reload의 보존 범위를 검증한다. [Khronos glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).
- 색을 담는 맵과 normal/roughness처럼 데이터를 담는 맵은 색 공간 처리가 다르다. 이를 명세와 입력 검사에 포함한다. [Three.js Color Management](https://threejs.org/manual/pages/color-management.html).
- 재질을 해제해도 공유 텍스처는 별도 수명 관리가 필요하며 자원 수 통계가 GPU 메모리 바이트 실측을 뜻하지는 않는다. 공유 범위를 정하고 geometry/material/texture를 각 소유권에 맞춰 정리한다. [Three.js 자원 해제](https://threejs.org/manual/pages/how-to-dispose-of-objects.html).
