# 5명 동작·업무 인계 개선 검증

2026-10-20 KST. [개발 계획](../dev-plan/implement_20261020_112001.md)에 따라 로컬 4180 제품을 개선했다. 외부 DB/LLM/서비스 연결과 DB 마이그레이션 없이 기존 계정·결과를 유지한다.

## 바뀐 동작과 화면
- 준비는 노트 쪽으로 시선·손을 조정하는 preparing, 현재 작성은 typing, 전달 후 검토는 reviewing으로 구분한다. 전체 검토 phase에는 문구도 ‘검토’로 일치시킨다.
- 기존 앉은 모델을 확장한 v4는 60개 클립, 4,184,596바이트(약 3.99MiB)다. 실제 bytes/hash는 [명세](../product/assets/manifest-v4.json)를 기준으로 한다. v1/v2/v3 에셋의 Git 변경은 없다.
- 인계 순간 전달자는 sending, 수신자는 receiving을 약 0.9초 재생하고 현재 업무 자세로 돌아간다. 시선은 실제 상대 자리 기준으로 yaw ±20도/pitch ±10도 이내에 제한한다. 시선은 매 프레임 원래 자세 기준으로 계산해 누적 회전을 막는다.
- 타이핑 반복에 짧은 휴지를 넣고 동료별 속도·위상을 고정해 동기화된 반복감을 줄인다. 마지막 담당자는 성공 반응, 나머지 동료는 짧게 확인하는 acknowledge 동작을 사용한다.
- 인계 카드는 전달자→수신자와 이미 완전히 공개된 이전 단계의 첫 항목을 최대 140자로 표시한다. 아직 작성되지 않은 다음 단계 내용은 사용하지 않는다. 현재 구도·사용자 선택을 유지한다.

## 검증 결과
- 전체 자동 회귀 **114/114 통과**. 기존 인증·게스트 최대 5명·공간 권한·Fake AI/인계/취소/저장과 기존 모델 검사를 포함한다. 추가 검사는 단계 경계·중복/오래된 응답·초기 기록·공간 전환·휴지/속도·정지·공개 요약·동작 줄이기 정책을 다룬다.
- 구문/타입/의존성 경계/제품 빌드 통과. v4 재수입, 60개 클립, 54개 접지점 고정, 독립 동작, 팔이 책상 위에 위치하는 표본과 제한된 머리 회전을 확인했다. 실제 렌더도 육안 검수했다. 모든 가능한 자세의 충돌을 수학적으로 증명한 검사는 아니다.
- 실제 제품 브라우저에서 나라→소라→준→민→레오 **4회 인계 모두 관측**했다. 전달·수신 두 동료의 클립, 이전 동료들의 reviewing, 이후 동료들의 preparing이 각각 일치했다. [실제 관측 JSON](../product/evidence/team-handoff/browser-qa.json).
- 로컬 서버의 독립된 두 시험 계정에서 같은 공동 공간 결과/단계 metadata와 답변 prefix 일치를 확인했다. 승인 전 본문 비공개, 정상 4회 인계, 첫 인계 후 취소, 장애, 새 실행 ID로 재시도 후 4회 인계를 통과했다. [HTTP 검증](../product/evidence/team-handoff/http-qa.json). `node --import tsx scripts/handoff-smoke.mjs`는 기존 비공개 시험 계정 파일이 있는 로컬에서만 재현한다.
- 실제 브라우저에서도 승인 대기→승인→실패→재시도(재승인 필요)→취소를 확인했다. 취소/실패 카드와 인계 반응은 즉시 제거된다. 정지 중 카메라를 변경해도 animationTime 0.677834가 유지됐고 서버 업무는 완료됐다.
- 새로고침 시 저장된 마지막 인계 카드는 복원되지만 인계 log는 빈 배열, 접근성 안내와 일시 반응은 비어 있었다. 과거 기록을 처음 여는 것만으로 연출을 재생하지 않는다.
- 실제 브라우저 뷰포트 280/298/319/390/600/601/768/1280px에서 문서 가로 넘침 없음. 상단 메뉴 nowrap/터치 높이 44px 유지. 인계 카드도 화면 안에 배치된다. 제품 콘솔 경고·오류 0개.

## 검수에서 발견하고 수정한 문제
- 2.5초 조회에서는 짧은 역할 단계를 건너뛸 수 있었다. 로컬의 활성 업무만 0.5초, 평상시는 2.5초, 숨김은 30초로 분리했다. 시작 시 기존 대기 폴링도 재예약한다. 기존 원격 실행의 조회 간격은 유지한다. 서버 진행 속도와 결과는 바꾸지 않는다.
- 탭 복귀 직후 오래된 스냅샷을 다시 그리면서 연속 관측 플래그가 너무 빨리 켜지지 않도록, 새 스냅샷을 적용한 뒤에만 복구한다. 여러 단계를 건너뛰면 최신 인계 하나만 표현한다.
- 정지 중 완료된 실행의 완료 반응이 재생 때 뒤늦게 나오지 않도록 관측 cue를 초기화한다. 일회 동작 종료 후 무조건 idle로 가던 경로도 현재 업무 자세로 복귀하게 바꿨다.
- 성능 검수 페이지의 초기 인라인 CSS는 CSP에 막혔다. 외부 CSS로 분리하고 고정된 구도로 다시 측정했다. 다른 검수 탭을 닫은 후 제품 탭의 실제 innerWidth를 확인하며 모바일 검수를 다시 수행했다.

## 성능과 검증 한계
- 같은 브라우저·1240×640 캔버스·pixelRatio 1에서 3초 측정 각 3회: v3 75.1/75.1/75.1fps, v4 75.1/75.1/75.2fps. 중앙값 모두 75.1fps, draw calls 827로 같았다. v4 전달 반응 포함 구간 1회도 75.1fps다. 이는 이 호스트의 측정값이며 실제 휴대폰 성능 보장은 아니다.
- `node scripts/build-motion-qa.mjs`로 로컬 검수 전용 `/assets/qa/index.html`을 임시 생성할 수 있다. 기본 제품 빌드에는 포함하지 않는다.
- 실제 모바일 기기와 OS의 동작 줄이기 설정 전환은 이번 검수에 사용하지 않았다. 브라우저 호스트는 보조 탭을 열어도 document.hidden이 false여서 실제 숨김 이벤트를 재현하지 못했다. 해당 정책·복귀·정지 조합은 결정적 입력 테스트로 검증했으며 이를 실제 OS/백그라운드 기기 시험으로 간주하지 않는다.
- 5개 외부 AI가 자율적으로 인계를 승인하는 기능은 아니다. 기존 하나의 Fake AI 실행과 공개된 단계 경계를 시각적으로 연결한다.
