# v12 일반 이동의 컵 제거·운반 접촉 보정

2026-10-23 KST. 사용자 제보: 이동할 때 모두 음료를 들고 컵이 손 아래 매달린 듯 보임. 외부 서비스 연결 없이 로컬에서 수정한다.

## 원인과 변경

- 2인 회의와 3~5인 회의의 시작 코드가 모두 `start({carry:true})`를 호출했다. 이동 경로의 문제가 아니라 회의 입장 조건에 컵 운반이 결합된 문제였다.
- v12 일반 회의는 컵 집기·테이블 컵 놓기·회수 없이 이동→착석→발언/기록→복귀한다. 준비/완료 조건도 빈손 활동에 맞춰 수정해 컵을 기다리며 멈추지 않는다. 양손은 보행·테이블 지지에 양보한다.
- 컵은 명시적 음용과 커피 준비에서 사용한다. 개인별 레시피가 활성화된 5명 모두 운반 시 컵을 손 앞에 두고, 손잡이를 몸 쪽으로 돌려 잡는다. 손목은 컵 중심보다 6mm 아래에 두어 컵이 손 아래 매달린 인상을 줄인다. 컵 자체는 수평을 유지한다.
- 손가락 목표는 기존 실제 손잡이 메시 위의 접촉점을 유지한다. 팔/손가락 길이와 컵 크기·소유권·GLB는 바꾸지 않는다. 자유 오른팔은 기존 개인별 보행을 유지한다.
- 기존 v11 비교 경로는 당시 컵 준비와 운반 자세를 보존한다. 기본 제품과 v12 비교 화면에 수정 동작을 적용한다.
- 안내 문구를 빈손 회의에 맞추고 커피 시연 직접 링크 `?play=1&demo=coffee&actor=nara`를 제공한다.

## 검증 근거

`product/evidence/personal-carry/`에 수정 이후 검사를 별도 보관한다. 이전 [잔여 검수](personal-final-qa.md)의 406개 전체 실행·실제 2시간 연속 검수는 이번 컵 수정 **이전**의 기준 결과이며, 수정 이후의 전체 회귀/2시간 검사로 합산하지 않는다.

- `carry-final-tests.tap`: 빈손 2인/5인 회의에서 이동·대화·취소·복귀 내내 컵이 책상에 고정되고 소유권 이벤트가 발생하지 않음을 검사한다. 실제 5명 커피 왕복에서 손잡이의 5개 패드 접촉, 고정 관절 도달 범위, 컵 수평/손목 높이/전방 위치, 자유 팔, 연속 보행 프레임을 검사한다. v11 정책 보존을 별도로 확인한다.
- 첫 연속성 검사에서 회전/정지로 샘플이 끊긴 구간의 두 비연속 보행 프레임을 비교해 실패했다. 프레임 간격이 실제 1/30초로 연속일 때만 이동량을 비교하도록 검사 코드를 수정했다. 초기 실패는 `carry-tests-initial.tap`에 보존한다.
- `final-team-cup-tests.tap`, `regression-tests.tap`: 기존 2~5인 회의 완료, 테이블/소파 접촉, 5명 전환·중단·정지, 개인별 음용·커피 대기열·복귀, 안경 우선권, 기존 v11 회의, 장면 공유 스키마 회귀를 검사한다.
- `browser.json`: 실제 exported GLB를 사용하는 로컬 브라우저의 빈손 5인 회의 완료/기록, 2인 회의 업무 중단, 커피 왕복, 실제 손잡이 접촉, x1/x1.5/x2/x3·정지·모션 축소·320~1440px 검수 결과를 기록한다. viewport는 실물 기기 검수와 구분한다.
- `typecheck.log`, `boundaries.log`, `static.log`: 타입·의존성 경계·제품 문법 검사를 실행한다.

## 적용 결과

수정 후 영향 회귀 **40/40 통과·실패/건너뜀 0·각 실행 exit 0**, 브라우저 5항목·페이지 오류 0, 타입·경계·문법 검사 통과. `summary.json`에 소스 지문과 실행별 수를 기록했다. 커피 사용의 pickup/out/brew/retrieve/home 각 단계에서 실제 업무로 중단해 컵의 책상 반환·예약 해제도 확인했다.

사용자 DB를 정상 종료 후 0600 권한으로 비공개 백업하고 관리 빌드를 4180에 적용했다. 실제 HTTP 앱/비교 번들·GLB 지문 일치, PGlite/Fake AI, 5명 v12, 단일 canvas, 빈손 회의 이동과 컵 운반의 실제 5개 손가락 접촉 및 이전 안경 접촉을 확인했다. 현재 적용 릴리스와 HTTP 지문은 `delivery.json`에 기록한다. 기존 서버 번들·원본 GLB·서버 전용 환경설정은 동일하다. 사용자 DB는 보존했으며 커밋·푸시는 수행하지 않았다. 실물 iPhone은 기존 offline/미완료 결정을 유지한다.
