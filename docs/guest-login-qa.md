# 게스트 최대 5명 검증

2026-10-20: 기존 공용 계정 하나를 신규 독립 게스트 방식으로 교체했다. 과거 공용 계정과 업무는 DB/백업에 보존하고, 공유 세션만 migration 010에서 종료한다. 과거 공용 공간을 새 방문자에게 재할당하지 않는다.

- 서버 DB 트랜잭션에서 유효 게스트 세션을 세고 최대 5개까지만 생성한다. 일반 계정 수 제한과 별개다.
- 각 새 로그인은 새 사용자·개인 공간·서명 쿠키를 사용한다. 비밀번호 계정이나 브라우저 토큰 응답은 만들지 않는다.
- 게스트 쿠키로 재접속/동일 로그인 요청 시 기존 세션을 사용한다. 고정 2시간 뒤 만료되며 일반 세션 갱신에 의해 늘어나지 않는다. 로그아웃하면 즉시 자리를 반환한다.
- 창을 닫는 것만으로 즉시 자리를 반환하지는 않는다. 정상 로그아웃 또는 만료를 사용한다.
- 만료/로그아웃 후 새 게스트 입장은 새 공간이다. 이전 업무를 보존해서 다시 보려면 일반 계정 사용이 적합하다.
- 게스트도 초대를 받아 공동 공간에 참여하면 해당 공간 기록은 참여자에게 공유된다. 개인 공간은 분리한다.
- 모든 체험 이메일 도메인은 일반 가입에서 예약 처리하고, 게스트 프로필/비밀번호/이메일 변경을 막는다.

검증: 로컬 DB와 실제 기기 내부 PostgreSQL의 두 앱 인스턴스에서 동시 6개 로그인 요청 중 5개 성공/1개 GUEST_FULL, 서로 다른 개인 공간, 타 공간 404, 로그아웃 후 재할당, 만료 후 재할당, 기존 기록 보존, Secure/HttpOnly/SameSite·DB 요청 제한을 통과했다. 외부 서비스/실배포 검증은 포함하지 않는다.
