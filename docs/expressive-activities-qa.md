# 움직임과 교감 · 활동 v5 로컬 검수

기준 main `8899fb9`, 활동 v4·공간 모델 v6. [개발 계획](../dev-plan/implement_20261021_091930.md)을 따라 나라 선행 → 5명 보행 → 구간 예약 → 역할 변주 → 상호 응답 → 개인 휴식 순서로 구현했다. 최종 검사·자원 회수 게이트를 통과해 로컬 제품 `/`의 기본 동작에도 활동 v5를 적용했다.

## 구현과 비교

비교 웹은 `/demos/activities/expressive/?play=1`이다. **v4 · 역할과 교감** / **v5 · 움직임과 교감**에서 같은 카메라·화질·조명·정지 상태로 전환한다. 기존 `/demos/activities/roles/` v4는 보존한다. 활동 v5는 절차적 런타임 버전이며 공간 모델은 기존 v6/105개 클립을 그대로 사용한다.

| 범위 | 구현 |
|---|---|
| 보행 | 직선 연결 병합, 최대 0.24m 코너 완화. 반경 0.34m 장애물 여유를 통과한 코너만 적용하고 좁은 코너는 디딤 회전 유지 |
| 접지 | 접지한 발 위치/방향 유지, 공중 발의 작은 신발 기울기, 지지 다리의 도달 범위를 만족하는 골반 높이 |
| 업무 복귀 | 곡선 중간에서 중단하면 지나온 측정 곡선을 역으로 사용. 샘플마다 멈추는 회전이 생기지 않도록 구분 |
| 이동 예약 | 세계 좌표의 0.4m 셀과 반경 0.5m 이동 여유, 독립 경로 최대 2명. 겹치는 경로는 책상/좌석에서 대기 |
| 역할 | 5명×대표/보조 2종=15종. 같은 소유권·접촉·회수 흐름에 다른 사용 궤적/읽기/잠깐 멈춤을 적용 |

| 휴식 | 인물별 기존 전신 휴식 2종 + 앉은 손목 풀기/어깨 내리기. 창가의 시선 전환·호흡과 작은 체중 이동 |
| 선택 | 기존 단일 선택기에 최근 행동·역할 선호·미완료 변주 기회를 통합. seed로 재현 가능. 활동 가능한 미참여자의 대화 기회와 상대를 먼저 확보하고 업무 중인 동료는 다른 동료를 막지 않음 |

**나라·준 이동 비교**는 소파와 창가로 향하는 독립 경로를 보여준다. **역할 동작 자동 선택/대표/보조 1/보조 2**와 기존 휴식·소파 대화·회의 버튼으로 개별 장면을 확인한다. 나라 선행 모드는 동작·소품·표정 보강 대상을 나라로 제한하고, 두 명이 필요한 후보 이동 버튼을 비활성화한다. 통로 예약 정책은 공간에 공통 적용한다.

## 구간 예약의 범위

자유 교행이나 이동 도중 구간을 하나씩 해제하는 방식은 아니다. 현재 공간에는 통로 중간에 새 대기 위치를 만들지 않고, 필요한 구간을 진입 전에 원자적으로 확보하는 보수적인 방식을 적용했다. 구간이 겹치지 않는 두 이동만 함께 허용하며, 교차/협소 경로는 한 명씩 이용한다. 두 사람 모두 진입 자원을 확보한 채 서로 기다리는 교착을 피한다.

소파 2석·회의 2석·창가 1곳은 기존 정원을 유지한다. 업무 복귀가 우선이며 대기 20초마다 우선순위를 올린다. 정지 시 예약과 시계가 유지되고 취소/복귀 완료/폐기 시 해제한다. 진단의 `traffic`에는 현재 이동자·최대 동시 이동·대기 시간·허가 횟수를 표시한다.

## 역할별 동작

| 동료 | 대표 | 보조 1 | 보조 2 |
|---|---|---|---|
| 나라 | 기획 메모 | 메모 다시 읽기 | 핵심에 밑줄 |
| 소라 | 태블릿 스케치 | 방향을 바꿔 스케치 | 화면과 스케치 비교 |
| 준 | 코드 화면 설명 | 다른 코드 영역 설명 | 손을 내리고 화면 확인 |
| 민 | 체크리스트 확인 | 항목별 체크 | 앞 항목 재확인 |

필기 선을 되돌리거나 체크 항목을 바꿀 때 펜을 작게 들어 옮긴다. 접촉 오차는 현재의 목표 펜 끝/작업점에 대한 오차이며, 공중 이동을 종이에 접촉한 상태로 표시하지 않는다. 실제 잉크·노트 데이터는 저장하지 않는다. 고정 손모양과 기존 얼굴 노드를 사용하며 전체 손가락 리그나 립싱크는 추가하지 않았다.

## 업무와 소유권

외부 DB/API와 서버 업무 계약은 변경하지 않았다. 실제 preparing/typing/reviewing과 어울리는 역할 변주를 사용하고 서버의 완료·승인·인계·저장 시각을 연출 때문에 늦추지 않는다. 업무가 소품 사용/이동을 중단시키면 안전하게 정리·복귀한다.

짧은 완료/인계 표정이 정리 중 사라지지 않도록 현재 런타임에서 해당 동료의 표시만 잠깐 보관했다가 정리 후 재생한다. 새 업무나 동료 제거가 오면 이전 표시는 폐기하고, 정지 상태에서는 표시 시간이 진행하지 않는다. 공간 변경/로그아웃에서 런타임과 함께 폐기한다. 서버 업무 큐나 새로운 업무 기록은 만들지 않는다.

## 한계와 후속

실물 모바일/터치·발열, 실제 OS의 모션 축소/백그라운드 동작, GPU 메모리와 장시간 heap 누수는 실측하지 않았다. 단기 JS heap은 아래 범위로 관측했다. Chrome 에뮬레이션과 소프트웨어 숨김 분기는 해당 범위로만 기록한다. renderer textures/geometries 수가 안정적인 것은 GPU/heap 전체 누수 검사의 대체값이 아니다.

좁은 통로의 자유 교행, 최대 3명 이상 보행, 책상 방문·화면 함께 보기, 소품 직접 전달, 전원 착석 회의, 정밀 손가락/얼굴 리그는 후속 범위다. 기존 3D 모델/텍스처·가구는 재제작하지 않았다.

## 최종 실제 30분 관측

30분 프로토콜은 6분 자율 → 20분 업무 ViewModel 도착 → 4분 자율 회복이다. 실제 서버 로그인·업무·인계·DB 저장은 별도 제품 검사로 확인했다. 외부 소비 스크립트는 30초마다 읽어 최종 보고 확인까지 약 1830초가 걸리며, UI 검사 종료 시각 1801초와 구분한다. 빠른 시뮬레이션으로 실제 경과 검사를 대체하지 않았다.
