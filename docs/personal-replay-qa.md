# 개인별 하루 · 직접 선택 동작 반복 회귀

2026-10-23 최종 통합 선검토에서 확인한 P2를 수정했다. 기본 5인 회의 페이지에서 `컵 한 모금`을 직접 선택한 뒤 구간 반복을 시작하면, 이전 `demo=team` 분기가 새 런타임에서 다시 5인 회의를 시작했다. 직접 선택한 3인 회의도 5인으로 바뀔 수 있었다.

## 수정

- 모든 시연·직접 실행 버튼을 `ActivityReplay`로 연결하고 **성공한 마지막 명령**의 종류, 동료, 상대, 참여자 순서·인원, 시나리오, 실제 역할 동작 변주를 저장한다.
- 구간 반복과 v11/v12 비교 재시작은 같은 저장 선택을 사용한다. 실패한 새 요청은 이전 성공 선택을 덮지 않는다. 선택값은 복사·동결하여 이후 UI 변경이 과거 명령을 바꾸지 못한다.
- 동료 라벨 클릭도 드롭다운 변경과 동일하게 반복을 취소한다.
- 원래의 구간 범위·고정 시간 전진·일시정지·실제 업무 도착 시 취소·우선순위 코드는 변경하지 않았다.

## 검증

`node --test product/tests/personal-replay.test.mjs product/tests/personal-inspection.test.mjs`

실제 `app.mjs`의 이벤트 핸들러를 작은 DOM·뷰·스케줄러로 실행한다. WebGL이나 DB를 만들지 않는다. 이전의 `launch(team)` 경로는 컵 및 3인 회의 단언을 통과할 수 없다.

- 기본 5인 회의 → 소라 컵 → 다른 동료 선택 → 반복에서 소라 컵만 시작.
- 민이 포함된 3인 회의 → UI 인원 변경·v11 비교 재시작 → 같은 3인/순서 반복.
- 창가·검토·역할 업무·커피·문서 방문·안경 버튼의 새 선택 연결 및 상대/변주 보존.
- 실패한 요청 이후 이전 성공 시연 보존, 자동 역할 변주의 실제 선택값 보존.
- 초기 `demo=visit&actor=jun`에서 자기 자신을 방문하지 않도록 상대 정규화 후 저장.
- 기존 inspection 검사는 배속·고정 간격·일시정지 잔여 시간·범위 경계·접촉 마커 자원 해제를 검증한다.

이 테스트는 실제 브라우저 렌더 품질이나 전체 동작 시뮬레이션을 대신하지 않는다. 최종 브라우저·전체 제품·장시간 검수는 루트 통합 결과에서 별도 확인한다.
