## 구현과 보존한 계약

- `personal-office/glasses.mjs`: 준 1인의 짧은 제스처·실제 안경 테 접촉점·시작 조건·취소·낮은 자동 빈도를 담당한다. 새 프레임워크나 메시/GLB를 추가하지 않는다.
- `PersonalMotion`이 단계 시간을 관리하고, 최종 gaze 이후 arm IK와 기존 손가락 솔버를 사용한다. 마지막 지지/가구 보정 뒤 실제 손가락 패드 오차를 측정한다.
- 팔/손가락 길이·발 위치·의자·안경의 부모/소유권을 바꾸지 않는다. 목표를 도달 범위로 잘라 성공으로 표시하지 않는다. 기존 5명 장면 스키마·105클립을 보존한다.
- 수동 취소는 손을 얼굴에서 떼고 회수한다. 높은 우선순위의 실제 활동은 해당 솔버에 즉시 양보한다. 다음 자동 안경 동작까지 최소 105 시각 초를 둔다.
- 5명 동작/업무·DB·Fake AI는 기존 로컬 실행 경로를 유지한다. 외부 연결·배포·커밋/푸시를 수행하지 않는다.

## 선행 검증과 보정

- `glasses-final.tap`: 5개 검사 통과. 실제 테/검지 패드 접촉·모든 손가락과 얼굴의 간격·고정 관절 길이/발·단계 전환 연속성, 모든 단계에서 업무/컵/이동/참가자 종료/취소, 정지·장면 왕복·실제 내보낸 GLB, 자동 스트레칭 시작 경계.
- 첫 근접 캡처에서 나머지 손가락이 과하게 펴져 보여 이완 프리셋을 보정했다. 초기 화면과 중단한 회귀/연속 검수는 `history/pre-finger-relaxation/`에 보존한다.
- 배속 검수 중 대기 중 자동 스트레칭이 안경을 중단하는 경계를 발견했다. 현재 안경 주기 동안만 다음 자동 스트레칭을 미루고, 실제 업무 중단은 유지했다. 이전 중단 로그는 `history/pre-idle-reservation/`에 구분한다.
- 초기 테스트 import/최적화 전 Face 노드 참조 오류는 검사 코드에서 수정했다. 얼굴·귀·코가 합쳐진 실제 exported skin mesh와 실제 테 메시를 검사한다. 검수 가정 때문에 제품의 접촉 기준을 완화하지 않았다.

## 최종 결과

아래 안경 통합 소스의 독립 검수는 완료했다. 이후 사용자가 요청한 컵 보정은 [별도 검수](personal-carry-qa.md)에 기록한다. 실물 iPhone은 offline으로 미완료이며, 마지막 로컬 적용에는 안경과 컵 보정을 함께 포함한다.

### 완료된 독립 검수
- `all-tests.tap` / `all-tests.exit` / `regression-summary.json`: 컵 수정 전 안경 통합 구현·테스트 소스에서 **406개 실행·406개 통과·실패/취소/건너뜀 0·exit 0**, 실제 3,087,175ms(약 51분 27초). 이전 399개 분할 재실행 결과와 합산하지 않은 하나의 전체 실행이다. 해당 시점의 구현·테스트 파일 277개 지문을 보존했다. 컵 수정 이후의 전체 406개 재실행으로 주장하지 않는다.
- `build-preflight.log`: 관리 빌드 준비 성공. 원본 공간 v9 8,768,140 bytes·105클립 유지, 현재 활성 릴리스와 서버 번들 해시 동일. 이 선행 빌드는 현재 실행 서버를 교체하지 않았으며 최종 검수 문서 갱신 뒤 로컬 적용 빌드를 준비한다.
- `visibility.json`: 실제 inactive tab·minimized window·정지 중 탭 전환에서 5초간 동작 시간 증가 0, 복귀 후 급진행 없음·재생/카메라·배속 입력·단일 canvas 통과. 강제 hidden 값이나 lifecycle 에뮬레이션으로 성공을 만들지 않았다.
- `browser.json`: 안경 실제 접촉/정지·4배속·실제 업무 선점·수동 회수·OS 모션 축소·v11 제외·320/390/768/1440px. 페이지 오류 0. 근접 프레임과 12초 영상(`glasses-inspection.mp4`)을 기록했다. 나머지 손가락의 자연스러운 굽힘도 실제 화면에서 확인했다.
- `regression-browser/browser.json`: 기존 업무 15종·컵 양손 지지·2인 회의 직렬화/복귀·방문/문서·소파 업무 중단·배속/정지·화면 너비·모션 축소·6회 비교 교체·GLB 오류 복구·준 자기 방문 방지 등 12항목 통과.
- `shared/shared-browser.json`: 합성 DB의 독립 계정 3개로 공동 관찰·지연 입장·정지 중 위치/소품 일치·보기 전용 제어 거절·제어권 교체·권한 강등·로그아웃 해제·모바일 viewport 단일 canvas 통과.
- `performance.json`: 1280×900/DPR1/기본 화질/동일 대기 카메라/5초×3회. v11/v12 p95 중앙값 모두 16.7ms, 각각 1,097 draw calls·773,350 triangles. 전체 회귀와 연속 검수가 병행 중이던 데스크톱 측정으로, 실물 모바일/독점 실행 벤치마크를 주장하지 않는다.
- 타입·의존성 경계·제품 문법 검사 통과 (`typecheck.log`, `boundaries.log`, `static.log`).

검수 코드 보정 기록: 연속 수동 시연에서 `scheduler.idle`만 기다리면 별도의 기본 스트레칭이 아직 팔을 사용 중인 순간에도 새 안경 시작을 요청할 수 있었다. 검사에서는 실제 제스처 시작 가능 조건을 기다리도록 수정했다. 실제 숨김 검수 뒤 자동 하루의 전체 취소까지 결합했던 초기 실행은 timeout으로 보존하고, 숨김/복귀 자체·복귀 후 카메라/배속 입력과 기존 생활 동작 취소 회귀를 분리했다. 초기 실패/중단은 history에 보존하며 최종 통과만으로 덮어쓰지 않는다.

메모리 검수 도구 보정: `waitForFunction`이 boolean 대신 engine/PersonalMotion 객체를 반환하면 Playwright의 원격 JSHandle이 해당 장면을 유지했다. 원래 화면 코드의 노드 해제와 구분하기 위해 모든 해당 대기를 boolean으로 바꾸고, `memory-retention.json`에서 16회 재생성·이중 강제 GC 뒤 폐기된 view/actor/scheduler의 WeakRef 잔존 수가 모두 0임을 확인했다. 제품의 회수 기준이나 한계를 완화하지 않았다. 원격 Handle이 누적된 중간 장시간 기록은 `history/qa-retained-wait-handles/`로 분리하고 성공 기록에 합산하지 않는다. 새 2시간 검수는 매 표본에서 폐기 객체 잔존 수 0도 검사한다.

실제 연속 검수 완료: `soak.json` 7,207.189초·24회 재생성·312개 표본·폐기 객체 잔존 0. 기준/최종 강제 GC 후 heap 24.60/27.67 MiB. Chrome GPU Process의 `gpu/angle/metal` 할당자 141.33→140.31 MiB로 기록했으며 전체 물리 VRAM 사용량을 뜻하지 않는다. Mac thermal pressure는 31개 표본 모두 nominal이며 휴대폰 온도나 섭씨 측정이 아니다. 컵 보정 전 번들 지문은 soak.json에 고정되어 있다.

로컬 적용 완료: 사용자 DB를 비공개 백업한 뒤 안경 보강과 후속 컵 보정을 함께 4180에 적용했다. `delivery.json`에서 실제 HTTP 번들/GLB와 관리 릴리스 지문, 준 안경 실제 접촉, 5명 v12·배속 진행·단일 canvas를 확인한다. 컵 보정의 후속 40개 영향 회귀와 브라우저 검수는 personal-carry-qa.md 및 별도 근거 폴더를 따른다.
