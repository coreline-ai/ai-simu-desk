검토 일시: 2026-10-19 KST

## 판정

기존 제안은 `needs revision`입니다. 업무 상태와 3D 표현 분리는 적절하지만, 전체 제품용 서버·DB·실시간 연결을 첫 시각 데모부터 도입하면 검증 목적보다 구현 범위가 커집니다. 아래 수정 사항을 반영한 **1차 시각 데모 계획은 `ready`**입니다. 이 판정은 제품 출시나 보안 인증에 대한 승인이 아닙니다.

## 근거와 검증 범위

- [공개 /auth 화면](https://deskrpg.com/auth)은 앞선 조사에서 출시 예고 화면으로 확인했습니다. 로그인 이후 화면의 실제 동작은 검증하지 않았습니다.
- [공개 저장소](https://github.com/dandacompany/deskrpg), 커밋 `740b3b7345e4fe682136d4f14ae82fc910853a1d`의 일부 파일을 정적으로 검토했습니다. 전체 코드 감사나 부하 테스트 결과로 확대 해석하지 않습니다.
- 원본은 `OfficeBridge`와 주입형 `HermesAdapter`를 통해 표현과 실행을 분리합니다. 이 패턴은 설계 참고 사항입니다.
- 3,166줄 시뮬레이션 파일과 2,230줄 소켓 파일은 책임 집중의 신호입니다. 줄 수 자체를 결함이나 취약점의 증거로 판단하지 않습니다.
- 현재 프로젝트는 신규 작업 공간입니다. 원본 코드나 에셋을 복사하지 않고 자체 파일과 생성 이미지를 사용합니다. 이미 원본 일부를 열람했으므로 엄격한 법적 의미의 클린룸 개발이라고 주장하지 않습니다.

## 구조와 계약

- `demo/src/domain.mjs`: 직원·실행 상태·검증·상태 전이. DOM, 타이머, 네트워크에 의존하지 않습니다.
- `demo/src/app.mjs`: UI 이벤트와 모의 실행 타이머. 모든 상태 변경은 도메인 함수를 통합니다.
- `demo/src/scene.mjs`: 아틀라스의 행/열 선택과 애니메이션 수명. 업무 상태를 직접 변경하지 않습니다.
- `demo/assets/manifest.json`: 실제 이미지 경로, 크기, 행 의미, 프레임 수와 제약.
- 사무실 전체에서 동시 모의 실행은 하나입니다. 직원 선택은 진행 중 실행의 소유자를 바꾸지 않습니다.
- `queued → running → succeeded | failed | cancelled`, `running → awaiting_approval → running`을 사용합니다. 승인 거절은 취소입니다.
- 중복 요청 키, 다른 실행 ID, 이미 처리한 단계, 종료 후 콜백은 상태를 변경하지 않습니다.
- 새로고침은 초기화입니다. 영속성·재연결 보장을 구현했다고 표시하지 않습니다.

## 테스트 검토

순수 상태 테스트는 정상 완료 외에 승인 없이 진행 차단, 취소 후 늦은 완료 차단, 중복 실행 차단, 단계 중복 차단, 실패 재시도와 잘못된 입력을 검증합니다. 브라우저에서는 실제 이미지 로딩, 프레임 변경, 키보드 입력, 모바일 오버플로, 모달 닫기, 움직임 정지와 업무 흐름을 확인합니다. 실측하지 않은 FPS·LCP·부하 수치는 보고하지 않습니다.

## 후속 제품 개발 전 필요한 결정

1. 사용자별·작업 공간별 권한과 인증 주체를 정합니다.
2. 작업/실행/외부 Hermes 카드의 원본 데이터 소유권을 엔터티별로 정합니다.
3. 저장된 실행, 중복 방지 키, 워커 임대와 중단 후 조정 규칙을 구현합니다. 비멱등 외부 작업을 무조건 재실행하지 않습니다.
4. 연결 상태와 실행 상태를 분리하고, 이벤트 저장·재조회·권한 재검증을 구현합니다.
5. 실제 3D는 대표 GLB 한 개로 카메라·폴리곤·텍스처·리깅·모바일 성능을 검증한 후 확장합니다.
